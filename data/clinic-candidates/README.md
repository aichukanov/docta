# Кандидаты на добавление в каталог

Клиники Черногории, которых ещё нет в БД, и очередь их добавления. Сюда же перенесена
гугл-таблица юзера с клиниками «на разбор / готово». Порядок работы — [PLAN.md](PLAN.md),
текущая очередь — [candidates.md](candidates.md).

## Файлы

| Файл | Что это | Кто пишет |
|---|---|---|
| `sheet-2026-10-08.json` | Гугл-таблица юзера на 2026-10-08, вкладки «на разбор», «Новые города», «на сайте нет врачей», «Красота», «готово». `n` — число отзывов из таблицы. В поле `resolved` для каждой строки указано, что это: клиника в БД (`db`, плюс `task` — что в ней доделать), сайт (`domain`), места Google (`placeIds`) или не клиника (`skip`). | руками, один раз |
| `site-checks.json` | Проверка сайтов кандидатов: есть ли прайс, список врачей, перечень услуг, ссылки на них, имена врачей. Проверено 2026-10-08 по сырому HTML (curl). | субагенты, по запросу |
| `SITE_CHECK_PROMPT.md` | Промпт субагента, которым делалась проверка сайтов, и схема записи. | руками |
| `overrides.json` | Что уже в БД под другим доменом или названием (`inDb`) и что не клиника (`exclude`). | руками |
| `candidates.json` | Итог: кандидаты с местами Google, отзывами, проверкой сайта и очередью; добавленные (`status: in_db`) и исключённые. | скрипт |
| `candidates.md` | То же, таблицами по очередям. | скрипт |

Сборка:

```
node scripts/clinics/build-clinic-candidates.mjs
```

Скрипт читает локальную БД. Добавленная клиника сама уходит из очереди в «уже в БД», если
совпал домен сайта, `google_place_id` или файл места отмечен в `data/google-places/progress.json`.
Иначе её нужно вписать в `overrides.json → inDb`.

## Откуда кандидаты

- **Места Google** из `data/google-places/<город>/*.json` (выгрузка Places API, март–сентябрь 2026).
  Берутся медицинские типы: аптеки, салоны, ветеринария и т.п. отбрасываются. Места вне Черногории
  (папка `bijelo-polje` захватила Прибой, Сеницу и Пријепоље, `ulcinj` — Шкодер) не учитываются.
- **Гугл-таблица.** Почти всё из неё есть и в выгрузке Google. Исключения — строки без места:
  Dental Health Montenegro, Cirkon Dental Lab, Dr Keković, Miljković & Jankov.

Кандидат — это один сайт (все места Google с этим доменом, например филиалы V Dental в Подгорице
и Будве) или одно место без сайта.

## Очереди

1. **Прайс и врачи.** На сайте есть прайс и хотя бы один врач. Импорт по образцу прошлых
   (`data/clinic-imports/`): прайс → услуги и анализы, врачи → `doctors`, отзывы.
2. **Хотя бы список услуг.** На сайте есть что-то из: перечень услуг, отдельные цены, врачи.
3. **Только отзывы.** Сайта нет или он пустой, но в Google ≥ 10 отзывов. Карточка клиники
   строится из места Google, отзывы — выгрузкой приложения юзера.
4. **Не в работе.** Сайта нет и меньше 10 отзывов.

Внутри очереди порядок такой: полный прайс → число врачей → перечень услуг → число отзывов.

## Отзывы

`reviews.google` — число отзывов из места Google на дату выгрузки. Это число устаревает:
выгрузке до полугода, `collectedAt` в каждом файле места. Перезапрашивать Places API без
разрешения юзера нельзя. `reviews.local` — сколько отзывов уже лежит в файлах мест. API
отдаёт максимум 5, поэтому больше пяти означает, что отзывы скачаны приложением юзера.

## Домены

Освободившиеся домены клиник собираются отдельно, в [`data/clinic-domains/`](../clinic-domains/).
Там же видно, у каких кандидатов сайт умер или припаркован.
