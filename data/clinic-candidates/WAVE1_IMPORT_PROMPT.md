# Промпт субагента: импорт клиник 1-й волны

Волна 1 из [PLAN.md](PLAN.md): клиники, у которых на сайте есть прайс и врачи. Раздано
2026-10-08 трём субагентам, у каждого свой список клиник.

---

## Задача

Подготовить полный импорт каждой клиники из твоего списка: карточка клиники, врачи, услуги
и анализы с ценами. Работай последовательно, клиника за клиникой, в указанном порядке.
Следующая клиника видит каталог, который ты дополнил для предыдущей. Отзывы в этой волне
не импортируются: в файлах мест Google их по 5 (лимит API), полную выгрузку юзер сделает
позже своим приложением.

## Жёсткие правила

1. **SQL не применять.** Ни локально, ни на проде: никаких INSERT/UPDATE/DELETE в БД.
   Локальную БД (`.env`, `mysql -uroot -p… docta_me`) можно только читать SELECT'ами —
   искать существующих врачей, услуги, анализы, категории, специальности, типы клиник.
   Применяет юзер.
2. **Только факты с сайта клиники.** Читай curl'ом сырой HTML, PDF — через Read (по страницам
   как изображение) или PyMuPDF. WebFetch для извлечения фактов не использовать: его пересказ
   достраивает поля, которых нет. Нет на сайте — нет в импорте. Не добавляй «логичные»
   услуги (консультация, контрольный осмотр), если их нет в прайсе или перечне. Не
   переводи название бренда или методики в generic, если сайт называет конкретное
   (и наоборот, не приписывай бренд, если сайт его не называет).
3. **Очевидное решай сам.** Если в каталоге один разумный кандидат — сопоставляй. В «Спорные»
   выноси только то, где кандидата нет или их несколько равноценных.
4. **Клиника в SQL — только по slug** (или `google_place_id`), не по числовому id: id на
   локали и проде расходятся. Врачи — по slug.
5. **Языки клиники (`clinic_languages`) — только SR**, если сайт прямо не заявляет приём на
   другом языке. Языки врача — только явно заявленные. Таблица без UNIQUE: `INSERT IGNORE`
   не спасает от дублей, перед вставкой — `DELETE … WHERE clinic_id = @clinic_id`.
6. **Фото врачей** — внешний URL с сайта клиники, ничего не скачивать.
7. **Не трогать общие файлы:** `data/clinic-pricelists/map.json`, `data/clinic-teams/map.json`,
   `data/google-places/progress.json`, `data/clinic-candidates/*`. Их обновит координатор.
   Не трогать чужие клиники.
8. **Не создавать новых специальностей и категорий** в коде (`enums/`, `i18n/`). Если для
   услуги нет категории или специальности — услуга в «Спорные», с пояснением.
9. `is_price_outdated` **не ставить** никому. Дату прайса записать в запись импорта; решение
   про outdated примет юзер.

## Как делать

Прочитай перед началом:

- `docs/import/CLINIC_DOCTORS_IMPORT.md` — врачи: найти или создать, транслитерация,
  специальности, языки, фото, личные услуги и цены по врачам.
- `docs/import/CLINIC_SERVICES_IMPORT.md` — услуги и анализы: что считать анализом,
  6 языков и slug для новых записей, sort_order, категории, специальности, синонимы.
- `docs/import/PRICELIST_FROM_PDF.md` — если прайс в PDF.
- `docs/rules/SQL_COLLATIONS.md` — шапка `SET NAMES` и `COLLATE` в новом SQL.
- `data/clinic-imports/README.md` — формат записи импорта.

**Карточку клиники** делай по образцу последних импортов:

- SQL: `server/sql/insert-clinic-radio-medic.sql`, `server/sql/insert-clinic-medicus-tim.sql`,
  `server/sql/insert-clinic-stomatoloska-ordinacija-musura.sql` (самоисправляющийся вариант:
  повторный прогон приводит клинику к тому же состоянию);
- запись импорта: `data/clinic-imports/radio-medic.json`.

**Поля карточки:**

- адрес, координаты, телефон, `google_place_id` — из файла места Google
  (`data/google-places/<город>/<файл>.json`), контакты в формате из
  `docs/import/GOOGLE_PLACES_IMPORT.md`;
- сайт, соцсети, email, описание — с сайта клиники;
- часы работы — с сайта, если указаны, иначе не заполнять.

Описания на 6 языках (sr, sr_cyrl, ru, en, de, tr) — только из того, что клиника пишет о себе;
кириллицу генерируй транслитерацией, латинские аббревиатуры не трогай (HbA1c, PSA, UZV, CT).

**Новые записи каталога** (услуги, анализы) создавай идемпотентно по slug. Каждую новую
запись допиши в свой файл `data/clinic-imports/_wave1-new-catalog-<агент>.json` с полями
`slug`, `name_en`, `name_sr`, `table`, `clinic`. Параллельно работают другие агенты, и
координатор сверит пересечения до применения.

## Что сдать по каждой клинике

1. `server/sql/insert-clinic-<slug>.sql` — клиника и врачи.
2. `server/sql/insert-clinic-<slug>-services.sql` — услуги, анализы, цены, привязки
   врач↔услуга. Применяется вторым, клиника резолвится по slug.
3. `data/clinic-imports/<slug>.json` — запись импорта:
   - источники с датами (дата прайса — откуда она взята);
   - `coverage` по блокам (отзывы — `pending`: ждут выгрузки);
   - `catalogAdditions`;
   - спорные позиции;
   - `status.appliedLocal` и `status.appliedProd` = `null`.

## Финальный ответ

Коротко, по каждой клинике:

- slug;
- сколько врачей: новых и найденных в БД — у кого и где;
- сколько услуг и анализов: с ценой, без цены, новых в каталоге;
- спорные позиции списком;
- что не удалось прочитать;
- пути к файлам.

Отдельно — вопросы к юзеру: только то, что нельзя решить по правилам выше.
