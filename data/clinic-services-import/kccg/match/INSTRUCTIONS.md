# Сопоставление позиций прайса КЦЦГ с каталогом docta.me

Ты получаешь батч позиций прайса Kliničkog centra Crne Gore (государственная
больница, Подгорица) — тех, для которых не нашлось готового соответствия по коду.
Для каждой позиции нужно решить: это **существующая** запись каталога или
**новая**. Новую — описать полностью (6 языков, категории).

## Входные файлы

- Твой батч: `E:\pet\docta.me\nuxt\data\clinic-services-import\kccg\match\in\<batch>.json`.
  Поля позиции: `code`, `name_kccg` (как напечатано в прайсе КЦЦГ — **главный источник смысла**),
  `name_fzocg` (название того же кода в госпрайсе FZOCG — только подсказка: в госпрайсе встречаются
  названия, съехавшие на соседний код), `section`, `price_eur`, `default_kind`.
- Каталог услуг: `E:\pet\docta.me\nuxt\data\clinic-services-import\kccg\ref\catalog-services.tsv`
  (id, slug, name_en, name_sr, cats, syn).
- Каталог анализов: `E:\pet\docta.me\nuxt\data\clinic-services-import\kccg\ref\catalog-labtests.tsv`.
- Категории: `E:\pet\docta.me\nuxt\enums\medical-service-category.ts`, `E:\pet\docta.me\nuxt\enums\labtest-category.ts`.
- Специальности: `E:\pet\docta.me\nuxt\enums\specialty.ts`.
- Правила названий: `E:\pet\docta.me\nuxt\docs\import\CLINIC_SERVICES_IMPORT.md`, разделы 1.1, 1.5, 2.1 и «Критерии разделения».

Ищи в каталоге Grep'ом по ключевым словам (сербский корень, английский термин, аббревиатура) —
каталог большой, просмотреть глазами его нельзя. Ищи и в услугах, и в анализах.

## Решение

- **existing** — только если запись каталога означает ТО ЖЕ САМОЕ: та же процедура/тот же
  аналит, тот же объект (орган, зуб, сторона), тот же метод, если метод в названии различает
  позиции (ELISA vs иммуноблот, IgG vs IgM, с контрастом vs без, первичный vs контрольный осмотр,
  ребёнок vs взрослый — если в каталоге такие варианты разведены). Похожее — не то же.
- **new** — если точного совпадения нет. Лучше новая запись, чем неверная привязка.
- **doubtful** — если сомневаешься между existing и new или не понимаешь, что за позиция
  (OCR-мусор, обрезанное название). Объясни в `note`. Такие позиции в SQL не пойдут.
- Две позиции твоего батча могут оказаться одной и той же услугой — тогда обе получают
  одно решение (тот же slug существующей или одинаковый `name_en` новой) и пометку в `note`.

## Услуга или анализ

`default_kind` — подсказка по разделу. Анализ (`lab_test`) — результат лабораторного исследования:
биохимия, гормоны, антитела, посевы, ПЦР, генетические тесты (кариотип, FISH, мутации).
Услуга (`medical_service`) — осмотр, консультация (в т.ч. генетическое консультирование),
процедура, взятие материала, диагностика инструментом. Если меняешь kind — скажи в `note`.

## Новая запись

- `name_en` — самый частотный медицинский термин, Title Case как в каталоге (посмотри соседние
  записи той же категории и повтори стиль). Не повторяй `name_en`, уже существующий в каталоге.
- `slug` — из `name_en`: нижний регистр, только a-z0-9 и дефисы.
- `name_sr` — сербская латиница, **иекавица** (ijekavski: «mlijeko», «dijete», «liječenje»), с диакритикой.
  Бери формулировку прайса, исправляя опечатки и OCR-искажения (данные важнее верности источнику),
  но не переписывая смысл. Без кода и без цены.
- `name_ru`, `name_de`, `name_tr` — полноценный перевод (немецкий и турецкий НЕ копировать с английского).
  Латинские названия микроорганизмов и международные аббревиатуры (CRP, PCR, HLA, ELISA, IgG) не переводить.
- `name_sr_cyrl` НЕ пиши — его сгенерирует скрипт.
- `categories` — имена из enum (например `["DENTISTRY"]`, `["IMMUNOLOGY","AUTOIMMUNE_ANTIBODIES"]`),
  для услуг — из medical-service-category, для анализов — из labtest-category. Мульти-категории — по таблицам документа.
- `specialties` — только для услуг: имена из `enums/specialty.ts`, если услугу выполняет врач конкретной специальности
  (для категорий из таблицы «категория → специальность» — обязательно).
- `sort_order` — 1 для первичного осмотра, 2 для контрольного, иначе не указывай.
- `synonyms` — по желанию, `[{"name": "...", "lang": "sr|en|ru|de|tr"}]`: аббревиатуры и устойчивые альтернативные названия.
  Не повторяй собственное название записи и не ставь слишком общих слов.

## Выход

Запиши `E:\pet\docta.me\nuxt\data\clinic-services-import\kccg\match\out\<batch>.json` (инструментом Write):

```json
{"batch": "<batch>", "items": [
  {"code": "K06008", "decision": "existing", "kind": "lab_test", "slug": "cryoglobulins", "id": 851, "note": ""},
  {"code": "D23016", "decision": "new", "kind": "medical_service",
   "name_en": "...", "slug": "...", "name_sr": "...", "name_ru": "...", "name_de": "...", "name_tr": "...",
   "categories": ["DENTISTRY"], "specialties": ["DENTISTRY"], "synonyms": [], "note": ""},
  {"code": "X99999", "decision": "doubtful", "kind": "medical_service", "note": "почему"}
]}
```

Каждый `code` входного батча — ровно одна запись в выходе. Ничего больше не делай: не запускай
SQL, не меняй другие файлы, не трогай БД. В ответе — одна строка: сколько existing / new / doubtful.
