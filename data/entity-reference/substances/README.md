# Справка о действующих веществах — формат батчей

Данные для `med_substance_reference_info` (миграция 024). Сборка:
`node scripts/entity-reference/build-substance-reference-sql.mjs` →
`server/sql/migrations/insert-med-substance-reference-info.sql` (идемпотентный upsert).

## Файлы

- `_roster.json` — ростер тира 1 (209 веществ), отсортирован по популярности:
  `priority`, `id` (= `med_substances.id`), `name` (черногорское, натуральный ключ),
  `name_en`, `name_ru`, `active_medicines`, `otc_medicines`, `atc`, `brands`.
  Сгенерирован из БД, руками не правится.
- `batch-XX.json` — по одному файлу на батч. **Свой файл на батч обязателен**: при
  параллельной работе общий массив теряет правки молча.

## Схема элемента батча

```json
{
	"substance_id": 178,
	"name": "desloratadin",
	"translations": {
		"ru": { "what": "…", "used_for": "…", "caution": "…" },
		"en": { "what": "…", "used_for": "…", "caution": "…" },
		"sr": { "what": "…", "used_for": "…", "caution": "…" },
		"de": { "what": "…", "used_for": "…", "caution": "…" },
		"tr": { "what": "…", "used_for": "…", "caution": "…" }
	}
}
```

`sr_cyrl` в батчах НЕ пишется: сборщик получает его транслитерацией из `sr`
(`common/serbian-transliteration.ts`), иначе две сербские локали разъезжаются.

## Формы выпуска — только из ростера

В `_roster.json` у каждого вещества есть поле `forms` — реальные формы из реестра ЧГ с числом
препаратов и сколькие из них без рецепта. **Домысливать формы запрещено**: у лоратадина
в реестре есть и сироп, и таблетки, а первая волна написала «выпускается в таблетках».

Правило: справка **не перечисляет формы** — форма и так показана на карточке лекарства прямо
над справкой, дублировать её незачем. Форму упоминаем ТОЛЬКО когда она меняет смысл:
разная рецептурность («наружные формы без рецепта, таблетки по рецепту») или ограничение
применения («вводит медработник»). Такое упоминание обязано совпадать с `forms`.

## Название вещества в тексте не повторяем

`what` **не начинается с названия вещества**: на карточке лекарства название напечатано
строкой выше и в самой строке справки, выходило «хлорфенамин — Хлорфенамин —
антигистаминное…». Пишем сразу суть: «Антигистаминное средство первого поколения…».

Это правило появилось после первой волны: около четверти текстов начинались с названия
(ru 49 из 209, sr 47, en 39) в двух формах — «Название — описание» и «Name je/is/ist
описание». Нормализованы разово скриптами в scratchpad, дальше пишем сразу правильно.

## Поля

| Поле | Смысл | Ограничения |
|---|---|---|
| `what` | что это за вещество и к какому классу относится | ≤160 знаков, одна фраза |
| `used_for` | когда применяют — типичные ситуации | ≤180 знаков, общие ситуации, не «у вас X» |
| `caution` | что важно знать | ≤220 знаков; рецептурность, сонливость, алкоголь, дети/беременность |

Дисклеймер («не заменяет консультацию врача») в данные НЕ пишется — это общая
i18n-строка на странице.

## YMYL-правила (те же, что для услуг и анализов)

- **Никаких дозировок, кратности и схем приёма** — ни в одном поле.
- Никаких «лечит X» / «избавляет от Y» — только «применяют при».
- Никаких рекомендаций «можно принимать самому» для рецептурных веществ.
- Спорные и опасные пункты (беременность, дети, алкоголь, вождение) — формулировкой
  «только по назначению врача», без собственных советов.
- Психоактивные, наркотические, онкологические и стационарные вещества: нейтральный
  факт-контент без интерпретации и без бытовых советов.
- Символ `|` запрещён (vue-i18n читает его как плюрализацию); перечисление — запятой.

## Стиль

Как в справках услуг и анализов: без воды, без маркетинга, короткими фразами.
Русский — эталон формулировки, остальные локали ему следуют по смыслу, а не пословно.
Сербский — иекавица (lijek, а не lek). Латинские аббревиатуры (NSAIL, ACE, COX-2)
писать латиницей: при транслитерации в кириллицу они защищены списком в сборщике.
