# Вычитка названий услуг и синонимы

Рабочее хранилище для правок `medical_services.name_*` и наполнения `medical_service_synonyms`. Зачем и что нашли — `docs/audit/service-names-2026-09.md`. Этот файл — инструкция тому, кто пишет батч (человеку или агенту), и описание конвейера.

## Конвейер

| Шаг | Скрипт | Что делает |
|---|---|---|
| 0 | `node scripts/services/scan-name-quality.mjs` | находит дефекты → `_flags.json` |
| 1 | `node scripts/services/build-name-review-roster.mjs` | раскладывает услуги по ростерам `_batch-fix-NN.json`, `_batch-review-NN.json` |
| 2 | агент/человек | пишет ответ `fix-NN.json` / `review-NN.json` по ростеру с тем же номером |
| 3 | `node scripts/services/validate-name-batches.mjs [--file …]` | проверка; без `--file` — все батчи разом, только так ловятся столкновения между батчами |
| 4 | `node scripts/services/build-service-names-sql.mjs` | собирает миграции, `name_sr_cyrl` и `sr-cyrl`-синонимы генерирует из `sr` |

Файлы с `_` в начале — входные данные и служебные списки, руками их не править. `_frozen-name-en.json` — значения `name_en`, на которые ссылаются неприменённые импорты клиник (`WHERE name_en = '…'`): поменяешь — импорт молча не найдёт услугу.

**Один батч — один файл.** Не дописывать в чужой: общий JSON-массив теряет правки молча.

**Номера от 90 — ручные батчи** (`fix-90.json` + `_batch-fix-90.json`): правки, которые агенты заметили вне своих ростеров. Их ростер пишется руками, сборщик ростеров его не пересобирает. Применяются последними в своём шаге, поэтому перекрывают автоматические батчи. Зачем каждая правка — `_decisions.md`.

## Инструкция для того, кто пишет батч

### Контекст

docta.me — каталог медицинских услуг клиник Черногории. У услуги шесть названий: `en`, `sr` (сербская латиница, черногорский узус — иекавица), `sr_cyrl` (генерируется из `sr` автоматически — **не пиши её**), `ru`, `de`, `tr`. Читают: жители Черногории, русскоязычные переселенцы, туристы. Название стоит в списке услуг, в заголовке страницы, в карточке клиники и в поиске.

Жалоба, из-за которой идёт работа: «часть переводов звучит странно или непонятно».

### Что в ростере

Массив услуг. У каждой:

- `slug`, `id`, `clinics` (в скольких клиниках есть), `categories`, `specialties`;
- `names` — текущие названия во всех шести локалях (`sr_cyrl` — только для справки);
- `existing_synonyms` — то, что уже есть в БД (в основном названия слитых дублей — это живые формулировки клиник);
- `fzocg` — официальное название позиции из государственного прайса FZOCG, если услуга с ним связана. Это первоисточник: хирургические позиции импортировали из него, и если перевод обрублен, полный смысл — там;
- `hints` — что нашёл сканер: `truncated_ru: пяточной`, `ekavica_sr: lekara`, `diacritics_sr: kicme → kičme`, `copy_of_en: de`, `short_vs_en: ru: 15/56`. Подсказка, а не приговор: `truncated_ru` и `short_vs_en` часто ложные.
- `шаг 1 уже поправил ru: «было» → «стало»` — в `names` уже лежит исправленное значение из батча `fix-*`. Считай его текущим: не переделывай без причины, а если меняешь — пиши в `names` итоговое значение целиком.

### Когда название менять

Меняй, если название:

- **обрублено** — «Перелом пяточной» (нет «кости»), «Вывих акромиально-ключичного» (нет «сустава»), «…в подвздошные» (нет «артерии»);
- **с ошибкой** — экавица, потерянная диакритика, опечатка, грамматика («Terapijski masaža»), смешение алфавитов;
- **калька или непонятный латинизм** там, где есть обычное слово: «Эксплорация» → «Ревизия», «Каутеризация» → «Прижигание», «Манипулятивная репозиция» → «Закрытая репозиция», «Каппинг» → «Хиджама (вакуумные банки)», «Аппликация лекарства» → «Введение препарата»;
- **не на том языке** или **порядок слов из прайса** — `Hernija TEP femoralna unilateralna`, `Fußhühnerauge chirurgische Entfernung`, `alçı longuetti`;
- **с неверным термином** — `MSCT Head` → `CT mozga` (МСКТ стал КТ, голова стала мозгом); `Rendgen cervikalnog (vratnog) dela vrata` (часть шеи вместо части позвоночника);
- **теряет смысл** относительно `name_en` / `name_sr` / `fzocg` — «Перелом ключицы» при `Clavicle Fracture (Closed or Open) with/without Fixation`;
- **выбивается из серии** соседних услуг в том же батче («Рентген X» у всех, «Рентгенография X» у одной).

Не меняй:

- то, что нормально звучит, — ради вкуса, синонимичной замены или «чуть лучше»;
- только регистр букв;
- устоявшиеся серии (`Первичный осмотр X` / `Контрольный осмотр X`, `Prvi pregled X` / `Kontrolni pregled X`) — не переписывай их в «Приём» или «Консультацию».

### Смысл неприкосновенен

- Все уточнения должны остаться во всех локалях: сторона (левый/правый/обе), количество (зубов, поверхностей, зон, сеансов, корней), длительность (30 мин, 24 ч), объём (1 мл), материал и бренд, «первичный / контрольный», «с ЭКГ / с УЗИ», вид анестезии, «у детей», «открытый / закрытый», «с фиксацией / без».
- **Цифры и единицы — ровно те же.** Валидатор ругается, если набор чисел поменялся.
- **Ничего не выдумывай.** Уточнение, которого нет ни в одной локали и ни в `fzocg`, не добавляй.
- Источник смысла — `name_sr` (ближе всего к прайсу клиники) вместе с `name_en` и `fzocg`. Если они **противоречат друг другу по смыслу** и однозначно не понять, что имелось в виду, — ничего не меняй и напиши `note`.
- Название позиции-диагноза из хирургического прайса («Перелом ключицы…», «Паховая грыжа…») в `ru`/`de`/`tr`/`en` можно превратить в название услуги: «Лечение перелома ключицы (закрытого или открытого) с фиксацией или без», «Операция при паховой грыже». Действие бери из источника (`repozicija` — репозиция, `fiksacija` — фиксация, `operacija` — операция); если действия в источнике нет — «Лечение …». `sr` держи близко к официальной формулировке `fzocg`, но грамматически целой.
- Длина — до ~120 символов. Сокращать длинное хирургическое перечисление можно только за счёт повторов, а не за счёт смысла.

### По языкам

**en** — Title Case, как у соседей. Меняй только явно сломанный английский: `X-Ray Abdomen Native` → `Plain Abdominal X-Ray`, `Pulpitis Treatment Single Root Machine` → `Pulpitis Treatment, Single-Root Tooth (Rotary)`. `name_en` уникален по каталогу. Значения из `_frozen-name-en.json` менять нельзя. Старое `name_en` сборщик сам добавит в синонимы — не дублируй его.

**sr** — черногорская **иекавица**: `ljekar`, `lijek`, `liječenje`, `dijete / djeca / dječji`, `tijelo`, `dio / dijela`, `mjesto`, `vrijeme` (но `vremena`), `mlijeko / mliječni`, `bijeli`, `cijeli`, `lijevi`, `koljeno`, `žlijezda`, `korijen / korijenski`, `crijevo`, `mjehur`, `ždrijelo`, `zjenica`, `njega`, `posjeta`, `zamjena`, `primjena`, `mjerenje`, `procjena`, `vježbe`, `svjetlo`, `izvještaj`, `izbjeljivanje`, `namještanje`, `prije`, `poslije`. Полная диакритика (`č ć š ž đ`). Термины как в черногорских клиниках: `pregled`, `kontrolni pregled`, `ultrazvuk` (`UZ`), `RTG snimak`, `CT` / `MSCT`, `MR`, `EKG`, `hirurg`, `opšte prakse`. **Кириллицу не пиши.**

**ru** — так, как это называется в прайсах российских клиник. `УЗИ`, `КТ`, `МСКТ`, `МРТ`, `ЭКГ`, `ЛОР`, `ПЦР`. Букву `ё` сохраняй, где она есть. Общепринятые латинские термины оставляй: экстирпация матки, аппендэктомия, остеотомия, биопсия, пункция, репозиция.

**de** — естественный немецкий порядок слов и составные слова: `Chirurgische Entfernung von Hühneraugen am Fuß`, `Erstuntersuchung Physikalische und Rehabilitative Medizin` (не `physiatrische`). `EKG`, `CT`, `MRT`, `HNO`, `Sonographie` / `Ultraschall`.

**tr** — естественный турецкий, как в турецких клиниках: `muayene`, `kontrol muayenesi`, `ultrasonu` / `USG`, `röntgeni`, `BT`, `MR`, `EKG`, `KBB`, `alçı ateli` (не `longuetti`).

**Бренды** (`Nobel Biocare`, `Straumann`, `Ivoclar`, `Invisalign`, `Botox`, `Tecar`, `Air-Flow`, `E-max`, `Bio-Oss`) — латиницей во всех локалях, как сейчас. Латинские названия микроорганизмов не переводятся. Международные аббревиатуры — по `docs/import/CLINIC_SERVICES_IMPORT.md`.

### Синонимы (только батчи `review-*`)

**Как ищет сайт.** Поиск берёт подстроку запроса и ищет её во всех шести названиях и во всех синонимах сразу, **от языка интерфейса не зависит**. Регистр и диакритика не важны (`kicme` найдёт `kičme`), **алфавит важен**: кириллический запрос не находит латиницу. Найденный синоним показывается в выдаче подписью «найдено по …».

Отсюда правило: **синоним — формулировка, которой реальный человек ищет именно эту услугу и которая не находится по её названиям.**

Добавляй:

- бытовое название рядом с медицинским — «УЗИ груди» к «УЗИ молочных желёз», `Ultrazvuk grudi` к `Ultrazvuk dojki`, «Снять швы»;
- аббревиатуру — «ОПТГ», «УЗДГ», «ЭхоКГ», «КТГ», `OPG`, `UZ`;
- другой медицинский термин для того же — «Дуплексное сканирование сосудов шеи», «Ортопантомограмма», `Orthopantomogramm`;
- другое название специальности — «Приём терапевта», «Врач общей практики», «Семейный врач»; «Реабилитолог» к физиатру;
- вариант написания — «Доплер» / «Допплер» (если в названии один, другой — синоним);
- бренд в местном алфавите — «Инвизилайн», «Штрауман», «Нобель Биокеа»;
- **экавский вариант ключевой фразы для `sr`** — многие пишут по-сербски: `Pregled lekara opšte prakse`, `Izbeljivanje zuba`, `Dečji stomatolog`. Это единственное место, где экавица разрешена;
- формулировку из `existing_synonyms` или `fzocg`, если она по сути другая и её пока нет.

Не добавляй:

- **подстроку своего названия** — она и так находится («УЗИ молочных» к «УЗИ молочных желёз» бесполезно);
- **название другой услуги** — даже близкой: «Маммография» ≠ «УЗИ молочных желёз», «ЭКГ» ≠ «Холтер ЭКГ». Синоним перетянет на себя чужие запросы. Валидатор проверяет по всему каталогу;
- **общее слово** — «операция», «осмотр», «УЗИ», «рентген», `pregled`, `operacija`, `examination`, `Untersuchung`, `muayene`;
- **одну и ту же строку в двух языках** — поиск от языка не зависит; латинскую аббревиатуру клади один раз, туда, где она родная;
- выдуманные термины и рекламу («лучшее УЗИ»).

Сколько: 0–4 на язык; обычно 1–3 для `ru` и `sr`, 0–2 для `en`, `de`, `tr`. **Ноль — нормальный ответ**, если добавить нечего (узкая хирургия почти всегда такая). Качество важнее количества.

Строка синонима оформлена как название: без точки и кавычек, до ~80 символов, первая буква заглавная (кроме аббревиатур с устоявшимся регистром). `sr` — только латиница (кириллицу соберёт сборщик), `ru` — кириллица.

### Батчи `fix-*` (шаг 1) — только механика

Ростер `fix` — услуги, у которых сканер нашёл механический дефект. Здесь **не вычитка**, а починка:

- `truncated_ru` — если русское действительно обрублено, восстанови полный смысл по `en` / `sr` / `fzocg`; проверь в той же строке `sr`, `de`, `tr` — обрыв там часто тот же, почини и его. Если окончание законное («Обработка раны — большая») — ничего не меняй;
- `ekavica_sr` — перепиши **весь** `name_sr` на иекавицу (все слова с ятем, не только найденное) и заодно поправь диакритику;
- `diacritics_sr` — поставь диакритику.

Прочее в `fix` не трогай, если оно не сломано тем же очевидным образом. **Синонимов в `fix` нет.**

### Формат ответа

Файл `data/service-names/<тот же номер без подчёркивания>.json` — для `_batch-review-07.json` это `review-07.json`. Строго JSON, массив. **Каждая услуга ростера — ровно один раз**, даже если ничего не поменял.

```json
[
	{
		"slug": "breast-ultrasound",
		"names": {},
		"synonyms": {
			"en": ["Breast Sonography"],
			"sr": ["Ultrazvuk grudi", "UZ dojki"],
			"ru": ["УЗИ груди"],
			"de": ["Mammasonographie"],
			"tr": ["Meme USG"]
		}
	},
	{
		"slug": "calcaneus-fracture-open-or-closed",
		"names": { "ru": "Лечение перелома пяточной кости (закрытого или открытого)" },
		"synonyms": { "en": [], "sr": [], "ru": [], "de": [], "tr": [] },
		"note": "только если человеку нужно принять решение"
	}
]
```

В `names` — только изменённые локали, итоговое значение целиком. В `fix` поле `synonyms` не нужно.

### Проверка перед сдачей

```
node scripts/services/validate-name-batches.mjs --file data/service-names/review-07.json
```

Все `ERROR` исправить, каждый `WARN` пересмотреть (подстрока своего названия — убрать; поменялись цифры — проверить). Гонять, пока нет `ERROR`.
