# Инцидент: Cloudflare Speed Brain ломал сайт во встроенном браузере Telegram — июль 2026

## Симптом

Ссылка на сайт, открытая из чата в Telegram (Android), сначала загружалась нормально. После тапа по
переключателю языка (`Русский`) вместо страницы показывалась заглушка встроенного браузера
**«Ошибка. Не удалось загрузить docta.me»** — с уже подменённым в адресной строке URL `docta.me/?lang=ru`.
В обычном браузере на том же устройстве всё работало.

## Что оказалось ни при чём

- **Код переключателя языка** (`components/language-switcher.vue`) — `router.replace` + cookie +
  `POST /api/auth/update-locale`, полной перезагрузки страницы не инициирует;
- **Серверные редиректы локали** (`server/common/redirect/regional-settings.ts`) — на `/?lang=ru`
  не срабатывают, цикла редиректов нет;
- **Прод** — `curl` на `/?lang=ru` стабильно отдавал `200` за ~0.15 с.

Прогон всего сценария в headless Chrome с UA телеграмного WebView тоже проходил успешно (заголовок и
h1 становились русскими) — воспроизвести ошибку «в лоб» не удалось. Зацепка нашлась в заголовках.

## Корневая причина

Cloudflare отдавал на каждой странице заголовок:

```
Speculation-Rules: "/cdn-cgi/speculation"
```

а по этому адресу лежало правило, инжектируемое фичей **Speed Brain**:

```json
{"tag":"cf-speed-brain","prefetch":[{"eagerness":"conservative","source":"document",
 "where":{"and":[{"href_matches":"/*","relative_to":"document"}]}}]}
```

`eagerness: conservative` означает, что браузер начинает префетч ссылки **в момент касания**
(pointerdown), ещё до клика. И на этот свой же префетч Cloudflare отвечал отказом:

```
HTTP/1.1 503 Service Unavailable
Content-Length: 0
Cf-Speculation-Refused: prefetch refused: not eligible
Vary: sec-purpose
```

Проверено на `/`, `/?lang=ru`, `/clinics`, `/services` — **отказ на всех URL сайта без исключения**.
Причина отказа: страницы динамические и отдаются с `no-store`, кешировать на edge нечего. То есть
Speed Brain на этом сайте не ускорял ничего, но генерировал пустой 503 на каждый тап по ссылке.

Современный Chrome отклонённый префетч отбрасывает и грузит страницу заново — поэтому в десктопном
браузере и в headless-прогоне проблема не проявлялась. Android System WebView, на котором работает
встроенный браузер Telegram, подхватывал пустой 503 как ответ на саму навигацию → пустой документ →
заглушка «Не удалось загрузить». Задевало это любой переход, просто на переключателе языка совпадение
особенно заметно: тот же путь, меняется только query, и SPA параллельно подменяет URL.

## Фикс (применён 2026-07-31)

Speed Brain выключен в панели Cloudflare: **Speed → Optimization → Content Optimization → Speed Brain**.
Правок в коде не потребовалось.

### Проверка после отключения

| Проверка | Результат |
|---|---|
| Заголовок `Speculation-Rules` на `/` | отсутствует |
| `GET /cdn-cgi/speculation` | `{}` вместо правила `cf-speed-brain` |
| `Sec-Purpose: prefetch` на `/`, `/?lang=ru`, `/clinics` | **200** вместо пустого 503 |
| Сценарий в браузере с UA телеграмного WebView | загрузка → тап «Русский» → `/?lang=ru`, h1 «Медицинские услуги в Черногории»; перезагрузка сохраняет язык, cookie `locale=ru`; переход на `/clinics?lang=ru` — «Клиники в Черногории (136)» |
| Ответы ≥400 с домена, JS-ошибки, падения рендерера | ноль |

## Как диагностировать это в следующий раз

Жалоба вида «в Telegram/Instagram сайт не грузится, а в обычном браузере всё нормально» — это почти
всегда edge-оптимизация, а не код:

```bash
# 1. есть ли на страницах спекулятивные правила
curl -sSI https://docta.me/ | grep -i speculation

# 2. что происходит с префетчем
curl -sS -o /dev/null -D - -H 'Sec-Purpose: prefetch' https://docta.me/ | head -20
```

Пустой `503` с `Cf-Speculation-Refused` = тот же баг.

**Правило на будущее:** edge-фичи Cloudflare, работающие через спекулятивную загрузку (Speed Brain,
prefetch-правила, Early Hints), этому сайту не подходят — ответы `no-store`, префетч всё равно будет
отклонён, а побочный эффект достаётся пользователям встроенных браузеров. Перед включением любой
такой фичи прогонять обе проверки выше.
