# Ревизия кода: производительность и SEO (2026-08-31)

Десять параллельных срезов кодовой базы, приоритет — производительность и SEO.
**73 подтверждённые находки**, статус на 2026-09-08: **66 исправлено, 6
частично, 1 открыта.** Все три критические закрыты.

Разбор жил в артефакте на claude.ai; это перенос в репозиторий — там ему не
место, документация должна быть рядом с кодом.

## Что осталось

**Одна открытая находка.**

- **I2 — пагинация не краулится.** Ссылок на страницы 2+ в разметке нет,
  переключение только по клику. Ждёт не рук, а дизайн-системы: ссылочная
  пагинация конфликтует с правилом «контролы только из библиотеки», а
  библиотека как раз переезжает. Задача расписана отдельно —
  `prd/element-plus-removal/TASK-pagination-links.md`, входит в итерацию 2
  (FR-10).

**Шесть частичных** — у каждой в разделе ниже есть пометка «Обновление» с тем,
что именно осталось:

|     | Что осталось                                                  |
| --- | ------------------------------------------------------------- |
| D1  | каталог клиник едет без пагинации (но уже без описаний)       |
| D3  | рефетч `/clinics` после гидратации из-за геолокации           |
| H4  | SSR-ответы не сжимаются на origin (нужен отдельный пакет)     |
| H6  | кэш ipapi — переменная процесса, квота делится на воркеры pm2 |
| C1  | все шесть локалей в каждом словарном чанке                    |
| R3  | `aggregateRating` не отдаётся                                 |

**R3 — единственная, которую нельзя закрыть работой.** Из 8194 отзывов
собственных ноль, все импортированы из Google Maps; считать по ним агрегат —
ровно тот self-serving случай, за который прилетает ручная санкция. Билдеры и
фильтр по источнику готовы и ждут появления своих отзывов.

## Что было сделано крупными мазками

Порядок — по тому, насколько правка меняла решения, а не по важности находок.

1. **Инъекция закрыта в корне.** Локаль больше не попадает в текст запроса:
   колонка перевода берётся по ключу из фиксированной таблицы. Побочно дешевле
   — `CASE` из шести ветвей на строку стал одним `COALESCE`. Написан валидатор
   локали и проведён через все 18 эндпоинтов; регрессионный тест сразу поймал
   одно пропущенное место.

2. **Утечка соединений закрыта классом, а не обходом 91 файла.** `release()`
   стал идемпотентным и вызывается по закрытию ответа. Здесь нашлась ловушка,
   которой в аудите не было: транзакции есть в 24 файлах, включая биллинг, и
   ранний возврат соединения при обрыве запроса отдал бы в пул соединение с
   открытой транзакцией — хуже исходной утечки. Поэтому границы транзакции
   отслеживаются, а release откладывается до фиксации или отката.

3. **Замер переопределил приоритеты.** Нагрузка на проде: API держит 354
   запроса в секунду, страница листинга — 3,5. Узкое место не база, а рендер
   Vue. Дальше работа шла туда, и главным рычагом стал кэш HTML на краю сети.

4. **Кэш HTML доведён до прода** (2026-09-08). Локаль стала зависеть только от
   адреса — это предусловие: пока один URL отдавал разным людям разное,
   кэшировать его было нельзя. Выбор посетителя вернулся отдельным воркером
   Cloudflare, до кэша и без обращения к origin. Граница «можно кэшировать»
   прошла по cookie сессии, а не по путям — иначе персональные данные из
   payload попали бы в общий кэш на любой странице.
   Всё описание — `docs/rules/EDGE_LOCALE_CACHE.md`.

5. **Sitemap: кэш, индекс, локали, `lastmod`.** Сборка кэшируется (1,00 с →
   0,09 с), `/sitemap.xml` стал индексом, каждая страница даёт по адресу на
   локаль (82 062 URL против прежних 13 678 — пять языковых версий не были
   видны для обхода вовсе), у сущностей появился `lastmod`.

6. **Мёртвые правила кэша заменены на матчащиеся.** Четыре правила были
   написаны в синтаксисе, который radix3 не поддерживает, и не срабатывали ни
   разу. Замена проверена прогоном реального набора через radix3.

7. **Запросы: пакетные операции вместо циклов.** Пересчёт рангов в худшем
   случае — 5,2 с и 8284 запроса против 149 мс и 19. Сортировка услуг
   перестала читать таблицу целиком. Всё сверено на временных копиях:
   расхождений ноль. Один результат — размен: страница клиники брала 11
   соединений из пула в 10 и укладывалась в 35 мс, теперь берёт одно и
   укладывается в 55. Работа та же, пропал параллелизм — зато две
   одновременные страницы клиник больше не морят голодом сайт.

8. **Микроразметка: убран повод для санкции и починен граф.** Устаревшие цены
   больше не уходят в разметку как точные, ссылки между сущностями перестали
   висеть на несуществующих узлах, врач размечен типом, который поддерживает
   рейтинг и отзывы.

9. **Первый экран.** Картинки статей 2419 КБ → 404 КБ при обычной плотности
   пикселей; убраны три источника сдвига макета, каждый бил по мобильному
   первому экрану. Из рендера убраны сотни компонентов, которые создавались
   только чтобы их спрятал CSS; карта перестала держать 126 Vue-компонентов и
   получила кластеризацию.

## Безопасность и устойчивость

### S1 · SQL-инъекция через параметр локали

**критично** · исправлено · перечитан лично

`localizedTextField` склеивает `locale` в текст запроса внутри одинарных кавычек. Значение приходит прямо из тела публичного запроса без проверки: `body.locale || 'en'`. Апостроф закрывает строковый литерал; `connection.execute` не помогает — SQL уже собран. Эндпоинты открыты без авторизации.

Места: `server/common/reviews.ts:31-40`, `server/api/clinics/reviews.ts:29`, `server/api/doctors/reviews.ts:34`

### S2 · Утечка соединений пула в 68 файлах

**критично** · исправлено

Паттерн «взять соединение → работать → `end()`» без `try/finally`. `end()` пропатчен в `release()`, поэтому исключение между захватом и освобождением навсегда сжигает слот. При `connectionLimit: 10` и `queueLimit: 0` десять ошибок подряд — и сайт висит до рестарта pm2. Ровно этот сценарий уже случался; фикс применили в двух местах и не распространили на остальные.

Места: `server/common/db-mysql.ts:44-47`, `server/api/clinics/list.ts:321-332`, `server/common/medicines/helpers.ts:21`

### S3 · Серверный гард админки не работает: `requireAdmin` без `await`

**критично** · исправлено · перечитан лично

Функция асинхронная, поэтому даже первый `throw` при отсутствии cookie уходит в отклонённый промис, а не в h3 — middleware продолжает работу. Прогрепал весь `server/`: это единственный неожиданный вызов, все 54 API-эндпоинта используют `await` корректно.

**Данные не утекают** — админские API защищены, страница дополнительно закрыта клиентским `middleware: 'admin-auth'`. Сломана серверная линия обороны и индексируемость: `/admin` отдаёт 200 анониму, при этом `Disallow: /admin/` не матчит путь без слеша, а сама страница — единственная из 62 без `useSeoMeta`, то есть без `noindex`.

Места: `server/middleware/redirect-routes.ts:33`, `server/common/auth.ts:9`, `public/robots.txt:3`

## Производительность бэкенда

### B1 · Sitemap пересобирается на каждый запрос без кэша

**высокое** · исправлено

~20 последовательных запросов, из них пять — полные листинги без пагинации (5081 услуга с тремя коррелированными `GROUP_CONCAT`, 0,65 с замерено). Затем 13 678 URL × 7 альтернатов склеиваются в строку ~12,9 МБ. Всё ради поля `slug`. На проде 1,92 с и `cf-cache-status: DYNAMIC`. Для ботов это готовый нагрузочный вектор — с учётом истории с `max_prepared_stmt_count` тем более.

Места: `server/common/sitemap/sitemap.ts:101`, `server/common/sitemap/utils.ts:26-29`

### B2 · Пересчёт rank_score — ~8074 одиночных UPDATE в цикле

**высокое** · исправлено

Четыре функции выбирают все строки и шлют по одному `UPDATE … WHERE id = ?` на строку, последовательно, на одном соединении: 1283 врача + 138 клиник + 5081 услуга + 1572 анализа. Запускается на старте сервера, конкурируя с холодным трафиком, и далее каждые 6 часов. Сводится к четырём `UPDATE … JOIN`.

Места: `server/utils/entity-ranking.ts:269`, `server/plugins/rank-score.ts:16`

### B3 · Страница клиники требует 11 соединений из пула в 10

**высокое** · исправлено

`fetchOne` вызывается четыре раза под `Promise.all`, каждый вызов делает 2–3 `executeQuery`, а тот берёт собственное соединение. Один рендер самоблокируется, две параллельные страницы клиник морят голодом весь остальной сайт. Все 11 запросов — по одной клинике и могли бы делить одно соединение.

Места: `server/common/clinic-items-summary.ts:251-261`

### B4 · Сортировка услуг делает индекс неприменимым

**среднее** · исправлено

`ORDER BY ms.sort_order IS NULL, …` — ведущий член это выражение, поэтому `idx_ms_sort_order` мёртв. `EXPLAIN` подтверждает: `type: ALL`, `key: NULL`, 5081 строка, `Using filesort` — на каждой странице `/services` и на каждом смещении пагинации.

Места: `server/api/services/list.ts:190`, `server/api/services/admin-list.ts:50`

### B5 · Сессия читается 2–3 раза за страницу

**среднее** · исправлено

`getCurrentUser` (7 LEFT JOIN) выполняется на каждом не-API запросе, следом `getUserPreferredLocale` делает второй запрос за колонкой, которую первый уже выбрал. Затем каждый вызванный страницей API повторяет `getCurrentUser` заново — мемоизации в `event.context` нет, хотя `requireAdmin` так уже умеет.

Места: `server/common/redirect/regional-settings.ts:47-50`, `server/utils/session.ts:104`

### B6 · Карточка врача тянет все отзывы, показывает пять

**среднее** · исправлено

`fetchReviews` вызывается без `limit`, в отличие от аналогичного места у клиник. До 59 строк с шестисторонним OAuth-join и сортировкой, включающей `EXISTS` на строку, плюс все ответы — и всё это ещё уезжает в payload, чтобы на клиенте быть обрезанным до пяти.

Места: `server/api/doctors/details.ts:126-129`, `pages/doctors/[doctorSlug]/index.vue:382`

### B7 · Инлайн LIMIT/OFFSET изнашивает кэш prepared statements

**среднее** · исправлено

Каждый номер страницы даёт отдельный текст запроса, а значит отдельный prepared statement. При 5081 услуге это ~254 смещения на LRU в 200 записей — пагинирующий трафик платит лишний round-trip почти на каждом запросе. Сам лимит 200 верен и должен остаться: биндинг `LIMIT ? OFFSET ?` убирает износ, не трогая его.

Места: `server/api/services/list.ts:143`, `server/common/db-mysql.ts:32`

### B8 · Фильтр «открыто сейчас» отключает пагинацию в БД

**среднее** · исправлено

Условие невыразимо в SQL, поэтому выбирается весь список (142 КБ, 0,11 с замерено) и режется в JS. Сегодня ограничено размером таблицы — и это тот же путь, по которому стор ходит вообще без `page`.

Места: `server/api/clinics/list.ts:160, 391-400`

### B9 · Услуги врачей: 604 строки джойна ради фильтрации в JS

**среднее** · исправлено

Берётся объединение всех клиник и всех специальностей по 20 врачам страницы, выгружаются все совпавшие пары, затем каждая отбрасывается или оставляется в JS. Замерено на первой странице листинга — это путь по умолчанию.

Места: `server/common/services.ts:333-490`

## Загрузка данных и SSR

### D1 · Весь каталог клиник уезжает в payload почти каждой страницы

**высокое** · частично

**Обновление:** Состояние на 2026-09-08: у `/api/clinics/list` появился режим `fields: "directory"` — ответ без описаний на шести локалях, и стор просит именно его. Остаётся то, что пагинации в запросе по-прежнему нет: приезжают все ~130 клиник, пусть и узкими записями.

Стор запрашивает список без `page`, а пагинация включается только при его наличии — значит отдаются все ~130 клиник с описаниями на шести локалях, контактами, купонами, рейтингами и разобранным расписанием на семь дней. Потребителям нужно семь полей: id, слаг, название, город, координаты. `pick`/`transform` не используется в проекте нигде.

Места: `stores/clinics.ts:21-28`, `server/api/clinics/list.ts:147, 257-319`

**высокое** · частично

**высокое** · исправлено

Ни `defineCachedEventHandler`, ни `cachedFunction` во всём `server/`. Пересчитывается на каждый запрос то, что меняется раз в месяц: полный список клиник, публичные слаги, опции фильтров лекарств, четыре эндпоинта комбинаций «город × категория», которые каждый листинг дожидается ради блока подсказок.

**высокое** · исправлено

На пяти семействах карточек детали и каталог клиник запрашиваются последовательно, хотя независимы. На странице клиники — шесть `await` подряд, из которых зависим только первый. Правильный паттерн уже есть в репозитории: листинги используют `Promise.all`.

Места: `pages/clinics/[clinicSlug]/index.vue:165-221`, `pages/doctors/index.vue:65-72`

**среднее** · исправлено

Места: `pages/clinics/[clinicSlug]/index.vue:221`, `components/clinic/working-hours.vue:24`

## Кэш и HTTP-слой

### H1 · Четыре правила кэширования статики не матчат ничего

**высокое** · исправлено

`/**/*.png`, `/**/*.svg`, `/**/*.webp` и `/*.js` написаны в синтаксисе, который radix3 не поддерживает: `**` должен быть терминальным. Проверено прогоном реального набора правил через radix3 из `node_modules` — работают только `/img/**`, `/photos/**`, `/uploads/**` и литералы. В итоге иконки, запрашиваемые с каждой страницы, отдаются вообще без `Cache-Control`, только с ETag, и ревалидируются на каждом визите.

Места: `nuxt.config.ts:106-117`

### H2 · SSR-HTML не кэшируется ни на байт

**высокое** · исправлено

**Обновление:** Закрыто 2026-09-08. Заголовки на кэшируемых маршрутах, `server/plugins/private-cache.ts` снимает кэш для вошедших, в панели Cloudflare стоят два Cache Rule и воркер локали. Проверено на проде: `HIT` на листингах и карточках, `DYNAMIC` + `private, no-store` при cookie сессии. Полное описание — `docs/rules/EDGE_LOCALE_CACHE.md`.

У рендерера в собранном рантайме нет ни `Cache-Control`, ни ETag, ни `Last-Modified`; Cloudflare HTML по умолчанию не кэширует. `prerender: false` навешен на `/**` скопом — включая главную, `/about`, `/terms`, `/privacy` и 19 статей, которые собираются вообще без обращений к БД.

Места: `nuxt.config.ts:70`

### H3 · Cookie-зависимый 301 без `Vary`

**высокое** · исправлено

Цель редиректа вычисляется из cookie, а 301 браузеры кэшируют бессрочно: посетитель с `locale=ru`, кликнувший ссылку `?lang=sr`, больше не попадёт на сербскую версию из кэша. ### H4 · Сжатия на origin нет вообще

**среднее** · частично

## SEO: микроразметка

### R1 · Устаревшие цены уходят в разметку как точные

**высокое** · исправлено

Флаг устаревшей цены существует и типизирован, на странице такая цена рисуется с пометкой «+X%» и тултипом — сайт сам заявляет, что реальная цена выше. В JSON-LD при этом уходит точное число. Фильтруется только положительность цены, в трёх билдерах сразу.

Для мета-описаний команда приняла ровно обратное решение и записала обоснование в комментарий: «оговорку в сниппет не унести». В разметку та же логика не доехала. Это единственный на сайте реальный повод для ручной санкции за spammy structured markup.

Места: `common/schema-org-builders.ts:1236, 855-907, 578-603`

### R2 · Граф идентификаторов разорван: ссылки ведут на несуществующие узлы

**высокое** · исправлено

Узел клиники получает фрагмент по своему типу — стоматология, больница, лаборатория, — а все ссылки на него захардкожены под общий тип организации. Общий тип возвращается только когда список типов пуст, то есть для реальных клиник ссылка не совпадает никогда. Работодатель врача, продавец услуги и поставщик каталога — висячие узлы без имени и типа.

Места: `common/schema-org-builders.ts:573, 770, 1289, 1030-1039`

### R3 · Агрегированный рейтинг не отдаётся ни на одной странице

**высокое** · частично

Билдеры это умеют, но рейтинг не передаётся никуда — сознательно, потому что серверный агрегат смешивает собственные отзывы со сторонними. Ограничение верное, следствие дорогое: единственный доступный каталогу rich result не используется вообще, хотя данные для честного расчёта уже на клиенте.

Оговорка: выигрыш пропорционален числу собственных отзывов. Прежде чем браться, стоит посмотреть по проду, сколько их реально есть — если единицы, приоритет смещается на их накопление, а не на разметку.

Места: `common/schema-org-builders.ts:67-73, 1093-1102`

### R4 · Врач без звания размечен как коммерческая услуга

**высокое** · исправлено

При отсутствии звания тип подменяется на `ProfessionalService` — это потомок `LocalBusiness`, а не `Person`. На этот узел вешаются четыре свойства с доменом «человек»: обращение, должность, знание языков, работодатель. То есть разметка утверждает, что живой человек — это бизнес-услуга.

Места: `common/schema-org-builders.ts:270-293, 763-768`

### R5 · Хлебные крошки размечены там, где их не видно, и с чужим именем

**среднее** · исправлено

Видимые крошки есть только на статьях, подстраницах клиник и страницах отзывов, а разметка отдаётся везде, включая все листинги и карточки. Плюс имя последнего элемента берётся из склеенного SEO-заголовка с разделителями — в крошку попадает строка вида «Холестерин | Биохимия | Подгорица», тогда как видимый заголовок другой.

Места: `pages/labtests/[labTestSlug]/index.vue:201-205, 314`

### R6 · URL сущностей строятся без языка и противоречат canonical

**среднее** · исправлено

Базовый билдер собирает адрес сущности без параметра языка, тогда как canonical его содержит. На пяти локалях из шести разметка объявляет главной страницей сущности другой URL. В списках то же: коллекция с объявленным языком перечисляет сербские адреса.

Места: `common/schema-org-builders.ts:194-203, 250-255`
