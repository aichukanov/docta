# Синхронизация состава врачей клиники с сайтом: правила для агента

Общая часть для агентов, которые приводят привязки `doctor_clinics` группы клиник в
соответствие с сайтами по карте `data/clinic-teams/map.json`. Промпт задаёт группу
клиник и особенности, здесь — что обязательно для всех. Агенты работают
**параллельно** в одном репозитории.

## Прочитать до работы

1. `docs/rules/SQL_COLLATIONS.md` — до первой строки SQL.
2. `docs/import/CLINIC_DOCTORS_IMPORT.md` — логика «найти или создать», slug,
   транслитерация, фото (внешний URL), языки (сербский всем), справочник специальностей.
3. `data/clinic-teams/README.md` и `data/clinic-teams/BACKLOG.md` — что уже решено.
4. Записи своих клиник в `data/clinic-teams/map.json` (поиск по `clinics[].slug`):
   `teamSources`, `siteDoctors`, `matched`, `possibleMatches`, `dbOnly`,
   `dbOnlyIsEvidence`, `dbOnlyCaveat`, `siteOnly`, `notes`.

## Источник

- Карта снята 2026-10-02. **Перед решением перепроверь сайт** curl'ом по
  `teamSources` (сырой HTML / wp-json / API). Состав мог измениться.
- WebFetch пересказывает и достраивает имена. Каждое имя подтверждай сырым ответом.
- Instagram и Facebook не читаются.

## Решения (утверждены юзером)

**Отвязка** (`dbOnly`):

- Отвязывай, только если сайт даёт полный список врачей клиники
  (`dbOnlyIsEvidence = true`), а врача там нет и при перепроверке.
- Сеть с филиалами (Milmedika, Hipokrat, Moj Lab): если врач на сайте есть,
  но в другом филиале, — это перепривязка, а не отвязка.
- Если у сайта есть `dbOnlyCaveat` (консультанты, стационар не публикуются), не трогай.
- Врача не удаляй. Остался без клиник — так и оставь (решение юзера). Не скрывай.
- В `clinic_medical_service_doctors` у отвязанного врача удаляются строки этой клиники.

**Добавление** (`siteOnly`):

- Добавляй врачей, которых сайт явно представляет как врачей клиники: имя, специальность.
- Сначала ищи в БД по имени и slug с учётом диакритики, порядка слов, двойных и
  девичьих фамилий:
  - **полный тёзка с той же специальностью** — тот же человек: только привязка;
  - **с другой специальностью** — обычно другой человек (так у Senad Kalač, Aleksandar
    Babović). Если сайт в остальном совпадает (то же учреждение, тот же город) — это
    один человек, и ему добавляется специальность. Аккуратно: врач бывает терапевтом
    в одной клинике и узким специалистом в другой.
- Новому врачу: `name_sr`, `name_sr_cyrl` (транслитерация по CLINIC_DOCTORS_IMPORT),
  `name_ru`, `name_en` (латиница без диакритики), `professional_title` как на сайте,
  `photo_url` — внешний URL, если есть. Специальности — только из справочника
  `specialties`, новых не заводи. Язык — сербский, плюс явно указанные на сайте.
  В `doctor_clinics.position` — должность, если сайт её называет.
- Не врачи: медсёстры, техники, администрация — не заводятся. Психологи, логопеды,
  физиотерапевты — только если в справочнике есть соответствующая специальность
  (например, 22 = PSYCHOLOGY) и в БД уже есть такие специалисты у других клиник.
- Специализанты (резиденты) — не заводятся.
- Шаблонные заглушки сайта («Dr Ivan Ivanović» со стоковым фото и т. п.) — не заводятся.

**Сомнительное.** Решай сам, если кандидат один и разумный. В отчёт с вопросом — только
то, где без юзера пришлось бы угадывать личность.

## SQL

- Файл: `server/sql/update-doctors-2026-10-<группа>.sql`, **без номера миграции**.
- Первая строка — `SET NAMES utf8mb4 COLLATE utf8mb4_unicode_ci;`.
- Клиники, врачи, специальности — **только по slug / name**: id локально и на проде
  расходятся. Перед сдачей проверь grep'ом, что `clinic_id = [0-9]` в файле нет.
- Создание врача — по шаблону «найти или создать» из CLINIC_DOCTORS_IMPORT:
  `SET @d = (… WHERE slug = …)`, затем `INSERT … WHERE @d IS NULL`. Так два агента,
  создавшие одного и того же человека, сойдутся на одной записи.
- Файл должен быть идемпотентным. В конце — блок VERIFICATION.
- **Проверка — только в транзакции с откатом:** node + mysql2 с
  `multipleStatements: true` и `flags: ['-FOUND_ROWS']`, затем START TRANSACTION,
  прогон, второй прогон (должен дать 0 строк) и ROLLBACK. Не применяй по-настоящему.
  Временные скрипты клади в scratchpad, не в репо.
- Состояние прода смотри через API (curl): `POST https://docta.me/api/doctors/details
  {"slug"}` → `clinicIds`, `specialtyIds`; `POST /api/doctors/list {"clinicIds":[prodId]}`;
  `POST /api/clinics/details {"slug"}` → prod id.

## Что сдать

1. SQL-файл.
2. `data/clinic-teams/decisions/<группа>.md`: по каждой клинике — отвязано, перепривязано,
   добавлено (новые / существующие), не тронуто и почему.

**Не трогай** `data/clinic-teams/map.json`, README, BACKLOG (общие файлы), код и чужие
файлы. Не коммить.

## Финальный ответ

- Цифры по клиникам: отвязано, перепривязано, привязано существующих, создано новых.
- **Список всех создаваемых врачей** — `slug | name_sr | специальности`. Координатор
  сверяет эти списки между агентами на тёзок.
- Вопросы, если остались, — каждый одной строкой с вариантами.
- Путь к SQL.
