# Сбор цен клиники с сайта: правила для агента

Общая часть для всех агентов, которые собирают прайс одной клиники по карте
`data/clinic-pricelists/map.json`. Промпт задаёт клинику, источник и
особенности. Здесь — что обязательно для всех. Несколько агентов работают
**параллельно** в одном репозитории, отсюда часть правил.

## Режимы

- **Новый прайс** — у клиники в БД цен нет, или есть только названия услуг без цен.
- **Синхронизация** — цены уже есть. Сверяешь с сайтом: что подорожало, что
  исчезло, что появилось. Образец — Milmedika:
  `data/clinic-imports/milmedika-prices-2026-10.md` и миграции `045`/`048`.

## Прочитать до работы

1. `docs/rules/SQL_COLLATIONS.md` — **до первой строки SQL**.
2. `docs/import/CLINIC_SERVICES_IMPORT.md`. В нём:
   - чем услуга отличается от анализа;
   - новые записи каталога (6 языков и slug);
   - категории, специальности, синонимы;
   - таблица `price` / `price_min` / `price_max` («od 100€» → `price_min`, диапазон → `price` + `price_max`).
3. `docs/DATABASE_SCHEMA.md`, разделы `clinic_medical_services`, `clinic_lab_tests`
   (флаги `is_price_outdated`, `is_obsolete`) и `medical_service_tariffs`.
4. `data/clinic-imports/README.md` — формат записи об импорте.
5. Для сканов PDF и картинок — `docs/import/PRICELIST_FROM_PDF.md` (PaddleOCR → LLM).
6. Запись своей клиники в `data/clinic-pricelists/map.json`, поиск по slug.
   Обрати внимание на поля `notes` и `recheckHint`.

## Источник

- Берёшь только URL из промпта и из карты. Цены только из открытых источников.
- Читаешь **curl'ом по сырому HTML или JSON**. Пересказ WebFetch выдумывает
  поля, поэтому годится максимум как подсказка, а каждый факт подтверждается curl'ом.
- Оригиналы прайсов, полученные вручную (в том числе без публичного URL), лежат в
  `data/pricelists/` — см. её README. Если у клиники в карте есть `localSource`,
  сверяйся и с ним. Туда же кладёшь оригинал, полученный не с сайта.
- Снимок источника сохрани в `data/clinic-pricelists/sources/<slug>/<YYYY-MM-DD>.<ext>`
  (html, json, pdf, jpg). Если файл больше 5 МБ, вместо файла запиши URL и sha256.
  Снимок нужен для будущих перепроверок: по нему видно, что изменилось.
- Запиши дату актуальности прайса: дату в документе, `modified` из wp-json,
  Last-Modified или год в имени файла. Укажи, откуда она взята.

## Сопоставление с каталогом

- Ищи совпадение в таком порядке:
  1. по коду (коды FZOCG вида `Y01004` — через `medical_service_tariffs` и коды других клиник);
  2. по `name_*` и синонимам: `medical_service_synonyms`, `lab_test_synonyms`.
- Решает код прайса, а не похожесть названия.
- Новую запись каталога заводи, только если совпадения точно нет. Все новые
  записи перечисли в отчёте отдельным списком: параллельные агенты могут
  завести одну и ту же услугу под разными `name_en`, и юзер сверяет такие списки между собой.
- `name_sr_cyrl` генерируй через `scripts/common/sr-cyrl-names.mjs`. Латинские
  аббревиатуры (HbA1c, PSA, HCV…) — через protected-список
  `scripts/common/sr-cyrl-protected.mjs`, и проверь результат глазами.
- Сомнительное сопоставление в SQL не попадает: перенеси его в `openQuestions`
  записи и в раздел «Спорные» отчёта.

## SQL

- Файл: `server/sql/insert-clinic-prices-<slug>.sql`. **Номер миграции не
  занимай** — параллельно пишут другие агенты, номер присвоит юзер.
- Первая строка — `SET NAMES utf8mb4 COLLATE utf8mb4_unicode_ci;`. В шапке
  комментарий: источник, дата среза, сводка цифр.
- Клиника и записи каталога — **только по slug**
  (`SET @clinic_id = (SELECT id FROM clinics WHERE slug = '…')`). id локально и на проде
  расходятся. Перед сдачей проверь grep'ом, что `clinic_id = [0-9]` в файле нет.
- Файл должен быть идемпотентным: `INSERT IGNORE` / `ON DUPLICATE KEY`.
  Правку цены в синхронизации пиши с условием на старую цену — тогда строку,
  которую поправили руками, файл не перезапишет.
- Старый прайс **помечай, но `is_price_outdated` по дате сам не ставь**. Старым
  считается прайс, у которого дата старше ~2 лет, или даты в документе нет и сам
  файл давно не менялся. Бывает, что клиника годами не меняет цены, и тогда старая
  дата не значит, что цены устарели. Пометка — это:
  - дата и откуда она взята — в шапке SQL и в `sources[].note` записи;
  - доводы за и против актуальности — в `openQuestions` и в разделе «Старые прайсы»
    отчёта.

  Решение о флаге принимает юзер. По умолчанию `is_price_outdated = 0`.
- Доводы, что цены устарели:
  - есть прайс новее — у другого филиала, в соцсетях, в Wayback;
  - клиника сама убрала цены с сайта, или сайт заброшен;
  - цены заметно ниже, чем у других клиник каталога на те же услуги.
- Доводы, что цены актуальны:
  - живой сайт по-прежнему ссылается на этот прайс как на действующий;
  - соседний прайс той же клиники обновлён, а этот оставлен как есть;
  - цены на уровне рынка или выше.
- Дата загрузки файла (Last-Modified, путь `/uploads/YYYY/MM/`) показывает, когда
  файл последний раз меняли, а не когда устарели цены. Одна она флага не обосновывает.
- Если промпт прямо велит поставить флаг, это решение юзера — ставь и укажи в шапке.
- Позиции, которых больше нет на сайте (синхронизация): ставь `is_obsolete = 1`,
  строки не удаляй. Если непонятно, чему позиция соответствует на сайте, — не
  трогай её и вынеси в «Спорные».
- В конце — блок VERIFICATION: SELECT'ы, которые показывают результат.
- **Не применяй SQL сам** — ни локально, ни на проде. Команды для юзера
  оформи по skill `migration-commands`.

## Состояние на проде

Локальная БД может отставать от прода. Прод можно читать без доступа к БД:

- `curl -s -X POST https://docta.me/api/clinics/details -H 'Content-Type: application/json' -d '{"slug":"…"}'` — даёт `id` на проде;
- `POST /api/services/list` с телом `{"clinicIds":[<prod id>]}` — цены и коды строк клиники (поле `clinicPricesData`); анализы — `POST /api/labtests/list` с тем же телом.

Используй curl, не node fetch. Если на API пришёл 403 — это Cloudflare, а не регресс.

## Что сдать

1. SQL-файл (см. выше).
2. Запись `data/clinic-imports/<slug>.json` по формату README. Если запись уже
   есть, обнови её: добавь новый источник, `excluded` не чисти.
3. Для синхронизации — `data/clinic-imports/<slug>-prices-<YYYY-MM>.md` в
   формате Milmedika: меняется цена / спорные / у нас есть, на сайте нет /
   на сайте есть, у нас нет.
4. Снимок источника в `data/clinic-pricelists/sources/<slug>/`.

**Не трогай** `data/clinic-pricelists/map.json` и `README.md` (это общие файлы), код,
i18n, чужие файлы. Не коммить.

## Финальный ответ юзеру

- Цифры: позиций в источнике, совпало с каталогом, новых записей каталога,
  изменённых цен, `is_obsolete`.
- Список новых записей каталога (`name_en` | `name_sr`) — для сверки между агентами.
- Спорные позиции и вопросы, которые требуют решения.
- Старые прайсы. По каждому — дата, откуда она взята, доводы за и против
  актуальности (см. раздел «SQL») и рекомендация, ставить ли `is_price_outdated`.
  Флаг в SQL ставь, только если так решил юзер.
- Команды применения (skill `migration-commands`).
- Строка для карты: `status`, URL прайса, `date_hint`, `lastChecked` — юзер внесёт её в `map.json`.
