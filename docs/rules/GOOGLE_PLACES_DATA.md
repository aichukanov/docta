# Данные Google Places: только чтение

`data/google-places/**` и `data/google-places-hours/**` — не кэш, а выверенный
каталог. Перезапрос Google Places API перезаписывает его машинным ответом:
правки исчезают молча, в сотнях файлов сразу, и в diff-е это выглядит как
обычное «обновление данных».

Читать эти файлы можно свободно. Запрещено без явного разрешения владельца
данных:

- ходить на `places.googleapis.com` / `maps.googleapis.com` любым способом
  (curl, node, python, WebFetch);
- запускать `scripts/clinics/fetch-clinic-working-hours.mjs`;
- писать в `data/google-places/**` и `data/google-places-hours/**`.

## Каталог полнее, чем ответ searchNearby

Это главное, чего не видно по структуре файлов. Карточки в
`data/google-places/<город>/*.json` собирал детальный проход: в них **полный**
список отзывов (у A3 Medical — 167) и поле `collectedAt`. `searchNearby`
отдаёт максимум **5** отзывов и `collectedAt` не ставит.

Поэтому перезапись карточки «свежими» данными — почти всегда потеря:
`bar/a3-medical.json` худеет с 253 КБ до 14 КБ, 167 отзывов превращаются в 5.
Ответ API при этом выглядит полноценным, и по объёму diff-а потеря не видна.

## Сборщик

`scripts/collectors/google-places.mjs` — обычный node-скрипт, как остальное
в `scripts/`. Запускается руками, в прогон тестов не попадает.

```
node scripts/collectors/google-places.mjs montenegro --yes   # вся страна
node scripts/collectors/google-places.mjs city <slug> --yes  # один город
node scripts/collectors/google-places.mjs cities --yes       # все города
node scripts/collectors/google-places.mjs split --yes        # разложить по папкам
```

Без `--yes` скрипт печатает план — что перезапишет и сколько запросов уйдёт
в API — и выходит, ничего не трогая. `montenegro` — это 360 запросов,
`cities` — 228, один город — от 6 (Беране, Цетине) до 78 (Подгорица).

`split` в API не ходит, но он и есть самая разрушительная команда: раскладывает
`all-montenegro.json` по папкам городов поверх детальных карточек. Поэтому по
умолчанию он **не трогает карточку, которая полнее приходящей**, и сохраняет
`collectedAt`. Перезаписать всё подряд — `--force`, и это осознанная потеря
отзывов.

## Три барьера

1. **Код.** `--yes` обязателен, иначе только план. `split` бережёт более полные
   карточки. Это единственный барьер, который едет в репозиторий и работает на
   любой машине.
2. **Права.** `.claude/settings.local.json`: `deny` на домены API, на скрипт
   часов работы и на запуск сборщика с `--yes`; `ask` на запись в каталоги.
   Правила действуют на агента, не на человека, и `.claude/` в `.gitignore` —
   на другой машине их нет.
3. **Откат.** `git checkout -- data/google-places/`. Файлы в индексе чистые.

Барьеры 1 и 2 ловят шаблоны команд. Правило важнее шаблона: новый способ
позвать сборщик они не поймают.

## Почему сборщик не в `tests/`

Раньше он лежал в `tests/scripts/parse-google-places.spec.ts` и был оформлен
через `test()` — ради раннера, а не потому, что это проверка. В
`playwright.config.ts` под него был отдельный проект `scripts`.

2026-10-26 этого хватило, чтобы агент, который хотел прогнать юнит-тесты,
увидел в конфиге проект рядом с `unit` и расширил прогон на «на всякий случай»:
`npx playwright test --project=unit --project=scripts`. Ушло ~590 платных
запросов, 141 карточка потеряла отзывы.

Путь `tests/` и форма `test()` читаются как безопасная проверка — против этого
никакая памятка не помогает, помогает только то, что сборщика там больше нет.
Юнит-прогон — `npx playwright test --project=unit`.
