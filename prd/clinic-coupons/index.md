# Купоны на скидку у клиник

## Зачем

Клиники и партнёрские сообщества дают скидки по купонам, а пациент об этом не
знает: акция живёт в чужом телеграм-канале и до карточки клиники не доходит.
Купон — единственное на странице клиники, что экономит деньги прямо сейчас,
поэтому он показывается первым блоком.

Первый и пока единственный купон: **Novi Standard Poliklinika** (Бар,
`clinic_id 64`) — −10%, купон партнёра **Montenegro Experte**, только при оплате
наличными.

## Модель данных

Таблица `clinic_coupons` (миграция `020-clinic-coupons.sql`, схема описана в
[docs/DATABASE_SCHEMA.md](../../docs/DATABASE_SCHEMA.md)).

**Почему отдельная таблица, а не колонки в прайсах.** Флаг устаревшей цены
(`is_price_outdated`, миграция 014) живёт в строке цены, потому что относится к
одной позиции. Купон — атрибут клиники: процент даётся сразу на весь тип
позиций, и у него есть свой срок, партнёр, картинка и условие оплаты.

Ключевые поля и решения:

| Поле                                                  | Решение                                                                                                                      |
| ----------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| `applies_to` SET('services','labtests','medications') | Обязательное. Купон бывает на услуги, на анализы или на то и другое сразу. Определяет, **где** купон вообще можно показывать |
| `payment_method` ENUM('any','cash','card')            | Скидка часто только за наличные. Условие обязано быть видно до кассы                                                         |
| `source_name`                                         | Партнёр, чью акцию транслируем; NULL — купон самой docta.me. Атрибуция текстом, без исходящей ссылки (решение пользователя)  |
| `image_url`                                           | Визуал купона; NULL — сайт рисует свой, локализованный (`ClinicCouponTicket`)                                                |
| `code`                                                | Кодовое слово, если клиника его требует; NULL — достаточно показать купон                                                    |
| `valid_from` / `valid_until`                          | NULL = «действует сразу» / «бессрочно, снимается вручную»                                                                    |
| `is_active`                                           | Снятие акции с витрины. **Не удаление**: по купону уже могли прийти пациенты, история нужна                                  |

Текст условий в БД не хранится — собирается шаблонами `i18n/clinic-coupon.ts` на
6 локалей.

## Правила, которые нельзя нарушать

1. **Купон показывается только там, где действует.** Карточка клиники
   (`ClinicSummary`) рендерится одним компонентом на каталоге клиник, страницах
   врача, услуги, анализа и лекарства. Тип позиции берётся из имени роута
   (`getCouponScopeByRoute` в `common/clinic-coupon.ts`), а не прокидывается
   пропсом через пять компонентов-посредников: цена в карточке всегда относится
   к сущности текущей страницы. Купон «на услуги» на странице анализа не
   появится. У Novi Standard 944 анализа — цена ошибки высокая.
2. **Ограничение не выдумываем.** При чтении неизвестное значение
   `payment_method` трактуется как `any` (`parseCouponPaymentMethod`): ложное
   «только наличными» — повод не прийти. При записи из админки, наоборот,
   валидация строгая: молча превратить «только наличными» в «любую оплату» —
   обмануть пациента у кассы.
3. **Партнёрскую акцию не присваиваем.** Если `source_name` заполнен, в условиях
   стоит «купон партнёра X», а не «наш купон».
4. **Оговорка про лабораторию — только тем, кого касается.** Строка «на анализы
   скидка не распространяется» показывается, если купон не покрывает анализы
   **и** у клиники анализы есть (`itemsSummary.labtests.totalCount > 0`).
5. **Заголовок собирается из падежных фрагментов**, а не из полных фраз:
   `CouponTitle` + `CouponScope*`, перечисление — `Intl.ListFormat`
   («на услуги и анализы»). Порядок фрагментов канонический, от порядка в SET не
   зависит. Для `Intl` сербской латинице нужен тег `sr-Latn`, иначе ICU
   подставляет кириллический союз «и» — см. `INTL_TAGS`.

## Где показывается

| Место                                                                           | Что видно                                                                                                                                                                                                     |
| ------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Страница клиники, **первый таб «Купоны»**                                       | Заголовок секции = сама скидка. Свёрнуто (200 px на всю секцию) — полоса купона с затуханием и кнопка на ней. Раскрыто — купон целиком, условия, шеринг. Клик по картинке — полный экран (`ImageZoomOverlay`) |
| Подстраницы клиники с ценами (`/clinics/:slug/{services,labtests,medications}`) | Компакт-строка `ClinicCouponBanner` со ссылкой на `#coupons`. Скрывается сама, если на позиции этой страницы скидка не действует                                                                              |
| Каталог клиник и страницы услуг/анализов/лекарств/врача                         | Купонная метка `КУПОН −10%` в карточке клиники **после цены** (`ClinicCouponBadge`): тултип с полным условием, клик ведёт на `?tab=coupons` — таб купонов с уже раскрытым блоком                              |
| Превью ссылки в Telegram / Facebook                                             | Сам купон — см. ниже                                                                                                                                                                                          |

**Метка кликабельна и ведёт в раскрытый блок.** Ссылка — `?tab=coupons`, это
конвенция таб-бара (`entity-page/tab-bar.vue` читает параметр на монтировании и
скроллит к секции), а сама секция по нему раскрывается сразу: переход по метке —
запрос показать купон, а не просто открыть клинику. Параметр `tab` исключён из
canonical (`NON_CANONICAL_QUERY_KEYS` в `common/url-utils.ts`), лишних URL в
индексе не даёт. Раскрытие срабатывает только на монтировании — клик по вкладке
«Купоны», когда пациент уже на странице, ничего не разворачивает.

**Метка обязана называть себя купоном.** Первую версию чипа — просто заливка
«−10%» — пользователь прочитал как обычную скидку, то есть как шум (2026-07-30).
Поэтому метка одна и та же в карточке клиники и в заголовке таба: пунктирный
талон со словом «КУПОН» и процентом (`ClinicCouponBadge`, вариант заголовка — с
`withTooltip: false`, рядом уже написано, на что действует). Заголовок таба =
метка + `CouponScopePhrase` («на медицинские услуги и анализы») — процент в нём
не повторяется. Полное предложение `CouponTitle` осталось для тултипа, `og:title`
и текста шеринга.

**Почему свёрнуто по умолчанию.** Блок стоит выше «О клинике». Купон может не
быть самой важной частью страницы, поэтому задача свёрнутого вида — сообщить,
что купон есть, не отжимая информацию о клинике вниз. В полосе показывается
**середина** картинки (`object-position: center`), а не верх: сверху обычно
логотип клиники, а размер скидки — по центру.

**Поведение «показать больше» общее для всего сайта** (DRY): контрол один —
`ShowMoreButton`, у него есть вариант `overlay` (кнопка лежит на затухании, не
добавляя блоку ~60 px), и переключение всегда симметричное — «Свернуть»
возвращает блок точно в исходный вид. Тем же паттерном работает
`CollapsibleContent` (описания клиник и врачей). Меняя поведение в одном месте,
меняйте в общем компоненте, а не локально.

## Превью ссылки (og:image)

`server/api/og/coupon.get.ts` отдаёт картинку купона как JPEG 1200×630.

- **JPEG, а не наш WebP**: Facebook рендерит WebP в превью ненадёжно.
- `fit: contain` на белом фоне — купон нельзя обрезать, на нём условия акции.
- Путь к файлу берётся **из БД по `couponId`**, а не из параметра запроса —
  иначе роут стал бы способом прочитать произвольный файл с диска.
- Любая ошибка (нет купона, снят, файл недоступен) → `302` на `OG_IMAGE`:
  ссылка не должна остаться вообще без превью.
- В `og:image` адрес с `?v=<8 символов имени файла>` (`getCouponOgImageUrl`):
  соцсети кэшируют превью по URL, при замене картинки адрес обязан меняться.
- У страницы клиники с купоном `og:title` ведёт со скидки, `twitter:card` —
  `summary_large_image`. `<title>` и meta description не тронуты, там SEO-текст.

После выкатки прогонять URL через **FB Sharing Debugger** — он кэширует превью.

## Админка

Блок «Купоны на скидку» в карточке клиники (`AdminClinicCouponsEditor`),
эндпоинты `server/api/clinics/coupons/{list,save,delete}.ts`, все `requireAdmin`.

- Список показывает и снятые, и просроченные купоны со статусом — их и надо
  править и возвращать в строй; публичная выборка их прячет.
- Картинка грузится штатным `AdminEditableField type="photo"` с категорией
  `coupons` (`VALID_CATEGORIES` в `server/utils/image-processing.ts`) — тем же
  механизмом, что логотипы клиник и фото врачей. Внешний URL скачивается к себе,
  а не хотлинкается: купон показывают на ресепшене, он не должен зависеть от
  чужого хостинга.
- «Снять с витрины» = `is_active = 0`. Удаление — только для ошибочных записей.

## Аналитика

- `coupon_opened` — открытие купона на полный экран (процент + партнёр).
- `coupon_shared` — клик «Поделиться» с каналом (`telegram` / `facebook` /
  `native`). Кнопки — обычные ссылки `t.me/share/url` и `sharer.php` плюс
  `navigator.share` на мобильных; **SDK соцсетей не подключаем** — это сторонний
  трекер и вопросы к cookie-баннеру.

## Что не в скоупе

- Онлайн-выдача персональных промокодов, учёт использований, ограничение «один
  на пациента» — механика купона целиком на стороне клиники.
- Купоны в кабинете клиники (владелец сам себе не заводит акции) — только
  админка.
- Отдельная страница `/coupons` со списком всех акций — при одном купоне это
  тонкая страница; имеет смысл, когда купонов станет несколько.
