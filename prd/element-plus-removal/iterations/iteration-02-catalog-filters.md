## Пагинация: почему её нельзя было починить на Element Plus

Находка 2026-08-31, проверена в коде. Это единственная причина, по которой переделка
пагинации ждёт этот PRD, а не сделана отдельной SEO-правкой.

**Что сейчас.** `components/pagination.vue` — обёртка над `el-pagination` с
`layout="prev, pager, next"`. Element Plus рендерит номера страниц как
`<li class="number">`, а не как `<a href>`, и разметку пейджера наружу не отдаёт —
ни слотом, ни пропом. На EP это чинится только перекрытием чужой внутренней разметки
или самодельным пейджером рядом — и то и другое против конвенций проекта
(«контролы только из библиотеки», кастомный CSS — лишь раскладка). Поэтому задача
и переехала в миграцию на свой кит: как только пейджер наш, `href` ставится штатно.

**Чем это стоит сейчас.** Страницы `?page=2` и дальше существуют, отдают 200 и
self-canonical на себя — но краулер попадает на них только исполнив JS, а в sitemap
их нет. Единственное упоминание следующей страницы в HTML — `<link rel="next">` в
`<head>` (`components/list-page.vue`, `paginationLinks`), а Google не использует
`rel=next/prev` с 2019 года. Итог: вглубь листингов вес с первой страницы не
передаётся вовсе, а карточки со второй и дальше страниц обнаруживаются только
через sitemap.

**Откуда брать href — источник уже есть, свой писать нельзя.** `buildUrl` внутри
`paginationLinks` (`components/list-page.vue`) уже собирает URL страницы через
`getCanonicalUrl` — именно затем, чтобы порядок параметров совпадал с canonical
этой же страницы. Своя сборка URL вернёт дубли по перестановке параметров, против
которых затевалась [итерация 3 PRD «Тихие 200»](../../silent-200-index-hygiene/iterations/03-canonical-params.md).
Значит: `buildUrl` выносится и передаётся в обёртку, а не переписывается.

**SPA-переходы сохраняются.** В SSR-разметке обязана быть настоящая `<a href>`
(для краулера и для «открыть в новой вкладке»), но обычный левый клик
перехватывается — `preventDefault` плюс текущая логика `update:current-page`, без
перезагрузки страницы. Клик с модификаторами (Ctrl/Cmd/Shift), средней кнопкой и
`target="_blank"` не перехватываются. Плавный скролл наверх у потребителей
(`items-page`, `reviews-page`) остаётся как есть.

**Исключение из [FR-6](../02-requirements.md).** `pagination.vue` — единственная
обёртка, чей внешний API расширяется: добавляется необязательный проп-построитель
ссылки (`page-href`). Кто его не передаёт — получает прежние кнопки без `href`.

| Потребитель | Нужен href | Источник URL |
|---|---|---|
| `components/list-page.vue` | ✅ да — 6 каталогов, основной органический трафик | `buildUrl` из `paginationLinks` (вынести и передать пропом) |
| `components/clinic/items-page.vue` | ✅ да — подстраницы клиник (services / doctors / labtests / medications), страница уже в URL через `pushQuery` | тот же приём поверх текущих query-параметров |
| `components/reviews-page.vue` | ✅ да — `/clinics/[slug]/reviews`, `/doctors/[slug]/reviews`, страница в URL через `router.push` | те же query-параметры |
| `components/map/clinic-popup.vue` | ❌ нет — попап карты, URL не меняется, краулера там нет | проп не передаётся, рендерятся `<button>` |


## Критерии приёмки

- **AC-1.** Grep-гейт контура (список файлов выше) → 0 вхождений EP.
- **AC-2.** Клавиатурный сценарий на /clinics: Tab до фильтра города → Enter/стрелки → выбор → Escape; фокус не теряется, видим индикатор.
- **AC-3.** Мобильная проверка (DevTools + реальный телефон): открытие селекта не скроллит страницу, тач-цели ≥ 44px, нет зума при фокусе инпута.
- **AC-4.** Мультивыбор (языки) — паритет: выбранные значения видны, снятие работает, clearable очищает.
- **AC-5.** Фильтры по-прежнему синхронизируются с URL-параметрами и срабатывают (e2e каталогов зелёные).
- **AC-6.** SSR: `npm run build && npm run preview` → каталог рендерится сервером с триггерами селектов, без гидрационных ворнингов.
- **AC-7.** Визуальное сравнение до/после на /clinics и /services — отличия только осознанные.
- **AC-8.** Пагинация краулится без JS: в HTML, полученном `curl` для `/clinics`, для подстраницы клиники и для страницы отзывов, каждый номер страницы — `<a href>`, и этот URL совпадает с canonical соответствующей страницы по составу и порядку параметров. Проверка: достать href из HTML, сходить по нему `curl` → 200 и self-canonical.
- **AC-9.** SPA сохранена: обычный клик по номеру страницы не перезагружает документ (полной навигации нет, состояние фильтров живо); Ctrl/Cmd-клик и средняя кнопка открывают страницу в новой вкладке.
- **AC-10.** `clinic-popup` на карте пагинируется как раньше — без `href`, URL страницы не меняется.

## Проверка

1. e2e: `npm run test:e2e` (каталожные сценарии).
2. Ручной прогон всех шести каталогов: каждый фильтр, пагинация, переключатель вид/карта.
3. Скрин-ридер smoke-тест (NVDA): селект города объявляет роль, состояние и выбранное значение.
4. Пагинация: `npm run build && npm run preview`, затем проверка HTML по AC-8 через `curl` (в dev-режиме смотреть разметку бессмысленно — нужна SSR-выдача сборки), и вручную — клик, Ctrl-клик, «назад» в браузере.
