# Итерация 1 — Честные коды ответа

**Статус: ✅ сделано 2026-07-28.** Все AC проверены на dev-сервере, typecheck и prettier зелёные.

**Даёт:** снимает причину 42% мусора в индексе Яндекса (602 URL) и закрывает неограниченную soft-404-поверхность.

Правки объединены одним принципом: **при сбое или отсутствии данных отдавать честный код, а не 200.** Делать одним коммитом, отдельно от остальных итераций — здесь трогается middleware, который выполняется на каждом запросе.

Пункт 1.3 (soft-500) в ходе работы **опровергнут проверкой** и снят — см. ниже.

## 1.1. `slug-redirects.ts`: падать громко и не терять соединение

Файл: [`server/common/redirect/slug-redirects.ts`](../../../server/common/redirect/slug-redirects.ts)

Сейчас:

```js
try {
    const connection = await getConnection();
    // ... запросы ...
    await connection.end();
    if (targetSlug && targetSlug !== param) { return { url, status: 301 }; }
} catch (error) {
    console.error('Error checking slug redirect:', error);
}
return null;   // ← сбой БД неотличим от «редирект не нужен»
```

Две проблемы в одном блоке:

1. `catch` глотает ошибку и возвращает `null`, то есть «редиректить не надо» → числовой URL отдаёт 200.
2. `connection.end()` стоит внутри `try` после запросов — при ошибке соединение не освобождается.

Нужно:

- **`try/finally` для соединения.** Освобождение обязано происходить всегда. Паттерн уже есть в проекте — `executeQuery` в `server/common/db-mysql.ts`, скопировать оттуда.
- **Различать «редирект не нужен» и «не смогли проверить».** Если параметр числовой (`isNumericId`) и проверка упала — это **не** «редирект не нужен», это неизвестность, и отдавать 200 с контентом нельзя. Бросать ошибку (`createError({ statusCode: 500 })`), чтобы краулер получил 500 и повторил попытку позже.
- **Для нечисловых параметров поведение оставить как есть** — там `null` означает «слаг актуальный, редирект правда не нужен», и это верно в 99.99% запросов. Ронять весь сайт из-за упавшей проверки таблицы `slug_redirects` нельзя: числовой ID — это узкий и заведомо неканоничный случай, а обычный слаг — основной трафик.

Это ключевое различие в правке: **строгость только там, где 200 гарантированно неверен.**

## 1.2. Catch-all: 404, `noindex`, без canonical, текст в SSR

Файл: [`pages/[...not-found].vue`](../../../pages/[...not-found].vue)

Нужно:

- `setResponseStatus(useRequestEvent()!, 404)` под `import.meta.server` — ровно тем же паттерном, что в `pages/labtests/[labTestSlug]/index.vue:49-51` и ещё 14 местах.
- `useHead`/`useSeoMeta` с `robots: 'noindex, follow'` и осмысленным `<title>` (сейчас `<title>` нет вообще).
- **Убрать canonical на несуществующий URL.** Canonical ставится в `app.vue` через `getCanonicalUrl` для всех страниц — нужно посмотреть, как его подавить именно здесь (проще всего — не рендерить canonical, когда страница отдаёт 404; решение по месту, но результат обязателен: в HTML 404-страницы `<link rel="canonical">` быть не должно).
- **Вынести `ErrorBlock` из `<ClientOnly>`.** Сейчас в SSR-HTML нет ни слова про ошибку. Если `ClientOnly` там стоит из-за реальной проблемы гидрации — разобраться и починить причину, а не оставлять как есть; текст ошибки обязан быть в серверной разметке.

Проверить, что 404 сущностей (`/doctors/bad-slug`) не сломался — он уже работает правильно и идёт другим путём.

## 1.3. ~~`error.vue`~~ — снято, дефект опровергнут проверкой

Планировалось создать `error.vue`, потому что из выгрузки Яндекса следовало, что страница
ошибки отдаётся с кодом 200 (7 URL с заголовком «500 - Internal Server Error | Nuxt» в
статусе SEARCHABLE).

**Проверено напрямую 2026-07-28 — вывод был неверен.** Временная страница с `throw` на
dev-сервере:

```
curl -H "Accept: text/html" http://localhost:3001/tmp-boom-test
  code=500  type=text/html;charset=utf-8
  <title>500 - Server Error | Nuxt</title>
```

Nuxt отдаёт честный 500. Soft-500 не существует.

**Правильное чтение выгрузки:** колонка `httpCode` у Яндекса не описывает URL как он есть —
это уже было доказано независимо, поскольку числовые URL, отдающие 301, тоже перечислены
с `httpCode 200`. Значит у тех 7 строк **устарел заголовок** (снят при обходе во время
аварии БД), а код 200 — от более позднего успешного обхода. Страницы живы; несвежий сниппет
освежится переобходом (итерация 4).

`error.vue` как таковой остаётся возможным улучшением (брендированная страница, `noindex`
на всякий случай), но это **не багфикс и не входит в скоуп** — YAGNI, пока нет
подтверждённой проблемы.

## Риски

- **Middleware на каждом запросе.** Ошибка в 1.1 роняет сайт целиком. Отсюда и решение бросать 500 только для числовых ID: если правка окажется неверной, пострадает узкий класс URL, а не весь трафик.
- **`ClientOnly` вокруг `ErrorBlock` может стоять не случайно.** Если при выносе полезет ошибка гидрации — разобраться, не откатывать вслепую.
- **`error.vue` перехватывает все ошибки Nuxt,** включая те, что сейчас как-то обрабатываются дефолтной страницей. Проверить, что 404 сущностей и `[...not-found]` не начали рендериться через `error.vue` вместо своих страниц.
