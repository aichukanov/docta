# Автотесты docta.me

Всё на Playwright, в трёх проектах (`playwright.config.ts`):

| Проект     | Каталог         | Браузер | Что проверяет                           |
| ---------- | --------------- | ------- | --------------------------------------- |
| `unit`     | `tests/unit`    | нет     | чистые функции и структурные инварианты |
| `chromium` | `tests/e2e`     | да      | живые страницы                          |
| `scripts`  | `tests/scripts` | нет     | утилиты-парсеры (запускать вручную)     |

## Запуск

```bash
# быстро, без браузера и без сервера
npx playwright test --project=unit

# e2e локально: dev-сервер поднимется сам (или переиспользуется запущенный)
npm run test:e2e

# e2e на проде
npm run test:e2e:prod

# один файл / одна группа
npm run test:e2e -- listings.spec.ts
npm run test:e2e -- locale.spec.ts -g "Edge Cases"

# HTML-отчёт
npm run test:e2e:report
```

`scripts` в обычный прогон не входит — по времени и по внешним вызовам.
Запускать точечно: `npx playwright test --project=scripts`.

## Структура

```
tests/
├── e2e/
│   ├── smoke.spec.ts        # страница вообще поднимается
│   ├── home.spec.ts         # главная
│   ├── navigation.spec.ts   # шапка и подвал
│   ├── locale.spec.ts       # локализация: query, cookie, SSR, переключатель
│   ├── listings.spec.ts     # общий контракт семи листингов и их карточек
│   ├── clinics.spec.ts      # только клиничное: часы работы, подстраницы
│   ├── articles.spec.ts     # статьи (своя разметка, не ListPage/EntityPage)
│   ├── seo.spec.ts          # robots, sitemap, редиректы, canonical, noindex
│   └── page-transition.spec.ts # регресс: переход не должен зависать
├── unit/                    # см. ниже
├── pages/                   # Page Object Model
│   ├── base.page.ts
│   ├── home.page.ts
│   ├── listing.page.ts       # один класс на все листинги
│   ├── entity-detail.page.ts # один класс на все детальные страницы
│   └── components/           # шапка, подвал
├── scripts/                 # парсеры (Google Places)
├── global-setup.ts          # прогрев маршрутов dev-сервера перед прогоном
└── utils/
    ├── constants.ts         # URL разделов
    └── sections.ts          # конфиг разделов + шаблоны URL
```

### Почему один спек на семь разделов

Все листинги рендерит `components/list-page.vue`, все детальные страницы —
`components/entity-page/index.vue`. Раньше это были четыре почти одинаковых
файла (clinics/doctors/services/medications), и при этом три раздела —
`labtests`, `medicines`, `insurance-companies` — не были покрыты вовсе.
Теперь контракт один, различия карточек лежат в `tests/utils/sections.ts`.
Новый раздел = одна запись в `LISTING_SECTIONS`.

Разделы `/medicines` и `/medications` — разные:
`/medicines` — реестр лекарств (пункт «Lekovi» в шапке),
`/medications` — лекарства, которые продают клиники.

## Покрытие

### e2e

- ✅ Главная, шапка, подвал, переходы по разделам
- ✅ Листинги ×7: карточки, названия, счётчик в заголовке, пагинация,
  переход в карточку
- ✅ Детальные страницы ×7: h1, контент, «к поиску», canonical
- ✅ Клиника: часы работы (7 строк + статус), подстраницы
  services/labtests/medications/doctors/reviews
- ✅ Статьи: листинг сверяется с `ARTICLE_SLUGS`, страница, крошки
- ✅ Локализация: `?lang=`, cookie, приоритет cookie над query, SSR,
  переключатель, невалидные и повторяющиеся значения, CLS
- ✅ SEO: robots.txt (в т.ч. 200 при cookie локали), sitemap.xml
  (абсолютные URL, все листинги, без дублей), 301 с числового ID на слаг,
  301 со снятого ID фильтра, 301 с `?lang=sr`, 404 на несуществующий слаг,
  canonical и hreflang на листингах, noindex на мусорном значении фильтра
- ❌ Авторизация и кабинет клиники, биллинг, админка, написание отзывов,
  карта. Локаль залогиненного пользователя тоже не покрыта: там были
  четыре `test.skip`-заглушки без фикстуры, они не проверяли ничего и
  удалены — вернуть, когда появится тестовый пользователь.

### unit

Быстрые, без сервера. Два типа: проверка чистых функций и структурные
инварианты (тест читает исходники и падает, когда новый файл заводится без
нужной проводки).

| Файл                        | Что сторожит                                        |
| --------------------------- | --------------------------------------------------- |
| `article-slugs`             | `ARTICLE_SLUGS` = файлы статей = листинг            |
| `bot-user-agent`            | живой браузер не принимается за бота                |
| `canonical-url`             | формы canonical не разъезжаются с sitemap           |
| `clinic-coupon`             | купон не обещает скидку там, где её нет             |
| `clinic-visibility`         | скрытая клиника не остаётся в выборках              |
| `clinic-working-hours`      | расчёт статуса «открыто/закрыто»                    |
| `doctor-visibility`         | скрытый врач не остаётся в выборках; 410 против 404 |
| `duplicate-surface-noindex` | новый листинг не заводится без noindex-проводки     |
| `packaging-label`           | склонение единиц; разделитель «;», а не pipe        |
| `product-schema-offers`     | Product объявляется только при живых ценах          |
| `retired-filter-ids`        | снятый ID фильтра уезжает на преемника одним хопом  |
| `serbian-transliteration`   | диграфы, placeholder'ы, генерация слагов            |
| `vue-teleport-unmount`      | версия Vue с фиксом зависания перехода              |

## Troubleshooting

**Локально таймауты на `page.goto`.** `nuxt dev` компилирует роут при первом
заходе. Против этого — `tests/global-setup.ts` (прогрев разделов до старта),
4 воркера вместо дефолтных 8 и таймаут теста 60 с. Если всё равно жмёт —
гонять по собранной сборке (`npm run build && npm run preview`).

**Раздел целиком отдаёт 500.** Скорее всего SSR-воркер `nuxt dev` выел
память: в ответе будет `JS heap out of memory`. Сервер, который поднимает
Playwright, стартует с `--max-old-space-size=4096`; свой, запущенный
руками, надо перезапустить.

**Тесты падают на проде.** Проверить доступность (`curl https://docta.me`),
посмотреть скриншоты и видео в `test-results/`. Прогон по проду идёт в один
воркер — так меньше шансов упереться в пункт ниже.

**Cloudflare и прод-прогоны.** Прод отдаёт `403` всему, что похоже на
автоматизацию. Замерено на одной машине в один момент:

| клиент                                                | результат |
| ----------------------------------------------------- | --------- |
| curl с браузерным UA                                  | 200       |
| `request.get()` (APIRequestContext)                   | 403       |
| Playwright Chromium, headless или headed              | 403       |
| headless настоящий Chrome                             | 403       |
| **headed настоящий Chrome без `--enable-automation`** | **200**   |

Поэтому в конфиге для прода включены `channel: 'chrome'`, `headless: false` и
снятый флаг автоматизации. Живых пользователей это не касается — обычный
браузер и curl получают 200.

Два следствия для тестов. Первое: `request.get()` на проде непригоден,
статусы и редиректы проверяются навигацией через `visit()` из
`tests/utils/http.ts`. Второе: `page.route` с подменой ответа API на проде не
работает вообще — переотправленный запрос приезжает challenge-страницей,
поэтому `page-transition.spec.ts` гейтится на localhost.

Симптом обманчивый: страница грузится с 200, а детальная показывает
«не найдено», потому что клиентский `POST /api/*/details` получил 403.
Проверять по трейсу:

```bash
unzip -o test-results/<падение>-retry1/trace.zip -d /tmp/tr
# в 0-trace.network искать статусы /api/ и запросы cdn-cgi/challenge-platform
```

**Порт 3000 может быть занят чужим приложением.** Прогон тогда молча уходит
в него, и падения выглядят как поломка docta (robots.txt отдаётся как
`text/html`, редиректы не срабатывают — потому что это вообще не наш сервер).
Проверять `<title>` на `localhost:3000`. Свой порт задаётся через
`E2E_BASE_URL` — `webServer.url` берётся оттуда же:

```bash
PORT=3100 node .output/server/index.mjs
E2E_BASE_URL=http://localhost:3100 npm run test:e2e
```

**Часть багов видна только на сборке.** `nuxt dev` не воспроизводит гонки,
которые ловятся на проде: другой планировщик, нет минификации, чанки грузятся
иначе. Зависание перехода из листинга в карточку на dev не повторялось ни
разу, а на сборке — 6 из 6. Прогон по сборке ещё и быстрее (2 минуты против 5) и стабильнее:

```bash
npm run build
node .output/server/index.mjs      # порт 3000, аналог pm2
npm run test:e2e                   # переиспользует уже поднятый сервер
```

Для читаемых стеков в минифицированном коде — временно `sourcemap: { client: true }`
в `nuxt.config.ts`, потом кадры разматываются через `@jridgewell/trace-mapping`
по `.output/public/_nuxt/*.js.map`.

**Зависание перехода из листинга в карточку — исправлено** обновлением Vue
до 3.5.40. Симптом: URL уже `/services/<slug>`, а на экране всё ещё листинг.
Причина, тесты-сторожа и как воспроизводить —
`tests/unit/vue-teleport-unmount.spec.ts` и
`tests/e2e/page-transition.spec.ts`.
